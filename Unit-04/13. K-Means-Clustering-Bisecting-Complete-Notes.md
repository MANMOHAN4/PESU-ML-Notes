## K-Means Clustering Fundamentals

### Definition

**K-Means Clustering** is a partitional clustering algorithm that:
- Divides data into K distinct, non-overlapping clusters
- Assigns each observation to nearest cluster center (centroid)
- Minimizes within-cluster variation (sum of squared errors)
- Requires pre-specifying number of clusters K

### Goal

Find cluster assignments such that:
```
Minimize: Total Within-Cluster Sum of Squared Errors (SSE)
SSE = ∑ᵢ₌₁^K ∑_{x ∈ Cᵢ} ||x - mᵢ||²

Where:
- Cᵢ = cluster i
- mᵢ = centroid (mean) of cluster i
- ||x - mᵢ|| = Euclidean distance from point x to centroid mᵢ
```

### Why K-Means?

✅ **Simple to implement** - Easy to understand and code  
✅ **Fast convergence** - Usually converges in few iterations  
✅ **Scalable** - Works with large datasets  
✅ **Effective** - Often gives good results in practice  
✅ **Interpretable** - Clear cluster centers and assignments

## Algorithm Overview

### High-Level Process

```
1. Initialization Step
   └─ Randomly choose K initial centroids from data

2. Assignment Step (Repeat Loop)
   └─ Assign each point to nearest centroid

3. Update Step
   └─ Recalculate centroid for each cluster

4. Convergence Check
   └─ If centroids changed → Go to step 2
   └─ If centroids stable → STOP
```

### Flowchart

```
         START
           │
           ├─ Initialize K random centroids
           │
    ┌──────┴──────┐
    │             │
    ├─ Assign Step │
    │ (compute distances)
    │
    ├─ Update Step │
    │ (recalculate centroids)
    │
    ├─ Check: Changed?
    │  YES → Loop back
    │  NO → STOP
    │
         END
```

## Initialization Step

### What is Centroid?

**Centroid** (or Cluster Center) = Mean of all points in cluster

```
For cluster C with points {p₁, p₂, ..., pₙ}:
centroid = (1/n) × ∑ᵢ pᵢ

For 2D points: centroid = (mean_x, mean_y)
For dD points: centroid = (mean₁, mean₂, ..., meanₐ)
```

### Initialization Process

**Step 1:** Specify desired number of clusters K

**Step 2:** Randomly select K data points from dataset

**Step 3:** Set these K points as initial centroids

### Example

**Data:** A(1,1), B(2,1), C(4,3), D(5,3)
**Choose K=2**

**Random Selection:** Pick A and C as initial centroids
- C₁ = A = (1,1)
- C₂ = C = (4,3)

### Random Initialization Effect

**Important:** Random initialization affects final clustering!
- Different random choices → Different final clusters
- No guarantee of global optimum
- May get stuck in local minima

## Assignment Step

### Process

For each data point:
1. Calculate distance to all K centroids
2. Assign point to nearest centroid
3. Point belongs to that cluster

### Distance Calculation

**Euclidean Distance** (most common):
```
d(x, c) = √[(x₁-c₁)² + (x₂-c₂)² + ... + (xₐ-cₐ)²]
```

**Manhattan Distance** (alternative):
```
d(x, c) = |x₁-c₁| + |x₂-c₂| + ... + |xₐ-cₐ|
```

**Cosine Similarity** (for text/documents):
```
similarity(x, c) = (x · c) / (||x|| × ||c||)
```

### Assignment Pseudocode

```
procedure ASSIGN(data_points, centroids):
    distance_matrix ← empty matrix[n_points × K]
    
    for each point p in data_points:
        for each centroid c in centroids:
            distance_matrix[p][c] ← calculate_distance(p, c)
    
    for each point p:
        nearest_centroid ← argmin(distance_matrix[p])
        assign p to cluster of nearest_centroid
    
    return cluster_assignments
```

## Update Step

### Process

After assigning all points:
1. For each cluster, calculate new centroid
2. Centroid = mean of all points in cluster
3. Update centroid position

### Centroid Calculation

**For cluster Cᵢ:**
```
New_mᵢ = (1/|Cᵢ|) × ∑_{x ∈ Cᵢ} x

Where:
- |Cᵢ| = number of points in cluster Cᵢ
- ∑ = sum over all points in cluster
```

**Example (2D):**
```
Cluster has points: (1,2), (2,3), (3,2)
New centroid = ((1+2+3)/3, (2+3+2)/3) = (2, 7/3)
```

### Update Pseudocode

```
procedure UPDATE(clusters):
    new_centroids ← empty list
    
    for each cluster C:
        points_in_cluster ← all points assigned to C
        
        if points_in_cluster is empty:
            keep_old_centroid(C)  {or pick random point}
        else:
            new_centroid ← mean(points_in_cluster)
            new_centroids.append(new_centroid)
    
    return new_centroids
```

## Convergence and Stopping Criteria

### Convergence Condition

**Algorithm converges when:**
```
Centroid positions don't change (or change negligibly)
OR
No points change cluster assignment
OR
Number of iterations exceeds maximum
```

### Stopping Criteria (Choose One)

| Criterion | Description | Pros | Cons |
|-----------|-------------|------|------|
| **No change in centroids** | Stop when centroids stable | Theoretically sound | May need many iterations |
| **No point reassignment** | Stop when no points switch clusters | More practical | May stop prematurely |
| **Max iterations** | Stop after N iterations | Guarantees termination | May not converge |
| **Low point movement** | Stop if <5% points move | Practical | Threshold dependent |
| **Low SSE reduction** | Stop if SSE improves <1% | Quality focused | Computationally expensive |

### Convergence Guarantee

**Important Property:**
- K-Means **always converges** (guaranteed)
- But converges to **local optimum**, not global
- Most convergence happens in **first few iterations**

## Sum of Squared Error (SSE)

### Definition

**SSE (Sum of Squared Error)** measures clustering quality:

```
SSE = ∑ᵢ₌₁^K ∑_{x ∈ Cᵢ} ||x - mᵢ||²

Where:
- K = number of clusters
- Cᵢ = cluster i
- x = data point
- mᵢ = centroid of cluster i
- ||x - mᵢ||² = squared Euclidean distance
```

### Interpretation

- **Lower SSE** = better clustering (points closer to centroids)
- **Higher SSE** = worse clustering (points spread from centroids)
- SSE monotonically decreases with each iteration
- SSE increases as K increases (more clusters = smaller SSE)

### Calculation Example

```
Cluster 1 contains: (1,1), (2,1), (3,2)
Centroid m₁ = (2, 4/3)

Point (1,1): distance² = (1-2)² + (1-4/3)² = 1 + 1/9 = 10/9
Point (2,1): distance² = (2-2)² + (1-4/3)² = 0 + 1/9 = 1/9
Point (3,2): distance² = (3-2)² + (2-4/3)² = 1 + 4/9 = 13/9

SSE_C1 = 10/9 + 1/9 + 13/9 = 24/9 = 8/3 ≈ 2.67
```

### Using SSE for Evaluation

- Compare SSE values across different K values
- Find "elbow" in SSE vs K plot
- Use SSE as objective function to minimize

| Medicine | pH | Weight Index |
|----------|-----|------|
| A | 1 | 1 |
| B | 2 | 1 |
| C | 4 | 3 |
| D | 5 | 4 |

**Task:** Cluster into K=2 groups using Euclidean distance

### Iteration 1

**Initialization:** C₁ = A(1,1), C₂ = B(2,1)

**Assignment Step:** Calculate distances

```
Distance from each point to centroids:
        To C1      To C2      Assign
A:      0.00       1.00   →  C1

C:      4.24       2.83   →  C2

```

**Cluster Results:**
- Cluster 1: {A}
- Cluster 2: {B, C, D}

**Update Step:** Recalculate centroids

```
C₁ = A = (1, 1)
C₂ = mean(B, C, D) = ((2+4+5)/3, (1+3+4)/3) = (3.67, 2.67)
```

### Iteration 2

**Assignment Step:** Calculate distances with new centroids

```
        To C1      To C2      Assign
A:      0.00       3.56   →  C1
B:      1.00       1.89   →  C1
C:      4.24       0.53   →  C2

```

- Cluster 1: {A, B}
- Cluster 2: {C, D}


## Elbow Method for Choosing K

### Problem: Unknown Number of Clusters

**Challenge:** How to choose K if number of clusters is unknown?

**Solution:** Elbow Method

### Elbow Method Process

**Step 1:** Run K-Means for K = 1 to K_max

```
K_max typically = √n or sqrt(n/2)
```

**Step 2:** For each K, calculate SSE

```
SSE(K=1), SSE(K=2), SSE(K=3), ..., SSE(K=K_max)
```

**Step 3:** Plot SSE vs K

```
SSE
 │     
 │    ╱
 │   ╱    (Steep drop)
 │  ╱
 │ ╱ ← Elbow (optimal K)
 │╱
 └─ ← Small reduction (plateau)
   
   K →
```

**Step 4:** Look for "elbow"

- Steep decline = significant K reduction
- Elbow point = optimal trade-off between SSE and K
- After elbow = diminishing returns

### Example

| K | SSE | ΔE | |
|---|-----|----|-|
| 1 | 150 | - |
| 2 | 95 | 55 | ← Large drop
| 3 | 65 | 30 | ← Drop
| 4 | 52 | 13 | ← Smaller drop (elbow)
| 5 | 48 | 4 | ← Diminishing
| 6 | 46 | 2 | ← Plateau

**Optimal K ≈ 4** (where drop becomes small)

## K-Means with Different Data Types

### Numeric Data (Standard)

**Default approach** - Use Euclidean distance
```
Works with continuous numerical features
Example: Age, Income, Temperature
```

### Text/Document Data

**Use Cosine Similarity instead of Euclidean:**

```
similarity(d1, d2) = (d1 · d2) / (||d1|| × ||d2||)

Where:
- d1, d2 = document-term vectors
- · = dot product
- ||d|| = magnitude/norm
```

**Applications:**
- Document clustering
- Text categorization
- Topic modeling

### Mixed Data Types

When data has both numeric and categorical:

**Approach 1: Encoding**
- Convert categorical to numeric (one-hot encoding)
- Apply standard K-Means

**Approach 2: Distance Modification**
- Use mixed distance metric
- Different weights for categorical vs numeric

**Approach 3: Separate Algorithms**
- Use K-Prototypes or K-Modes
- Extensions of K-Means for mixed data

## Limitations of K-Means

### Limitation 1: Differing Cluster Sizes

**Problem:** K-Means struggles with clusters of different sizes

```
Actual clusters:        K-Means result:
  ▲ Small cluster          ▲ Merged wrongly
  ▼ Large cluster          ▼
```

**Why:** K-Means optimizes SSE globally, not cluster sizes

### Limitation 2: Differing Cluster Density

**Problem:** Clusters with different point densities

```
Actual:              K-Means clustering:
Dense cluster        Misaligned boundaries
Sparse cluster       (assigns by distance)
```

**Why:** Centroid-based approach insensitive to local density

### Limitation 3: Non-Globular Shapes

**Problem:** Non-spherical cluster shapes

```
Actual (crescent):   K-Means (circular):
  🌙                   ●●
                       ● ●
```

**Why:** Euclidean distance assumes spherical clusters

### Limitation 4: Outlier Sensitivity

**Problem:** Outliers distort centroid calculations

```
Centroid moved by outlier:
    ╳ Outlier
    |
    ├─ New centroid ← Pulled away
    |
    O O    ← Normal points
    O O
```

**Solution:** Preprocess to remove outliers

### Limitation 5: Local Optima

**Problem:** Converges to local minimum, not global

```
Global optimum:      Local optimum:
Best clustering      Suboptimal clustering

Different initializations → Different results
```

**Solution:** Multiple runs with different initializations

### Limitation 6: K Pre-specification

**Problem:** Must know K beforehand

```
If true K unknown → Need elbow method or domain knowledge
```

### Limitation 7: Empty Clusters

**Problem:** Some clusters may end up empty

```
K = 4 specified, but:
- Cluster 1: {points}
- Cluster 2: {empty}  ← No points assigned!
- Cluster 3: {points}
- Cluster 4: {points}
```

**Solutions:**
- Pick point with highest SSE
- Pick point farthest from nearest centroid
- Initialize new centroid in dense region

## Initial Centroid Selection Issues

### The Problem

**Example with K=10:**
- Probability both centroids from same true cluster: Very high
- Result: Poor initial configuration
- May not recover with iterations

### Statistical Reality

```
If K 'real' clusters and we pick K random centroids:
P(one from each cluster) = K! / K^K

For K=2: 2!/2² = 0.5 (50% chance)
For K=3: 3!/3³ = 0.222 (22% chance)
For K=10: 10!/10^10 ≈ 0.00036 (0.036% chance!)
```

**Implication:** Random initialization very likely to be poor!

### Solutions

**Solution 1: Multiple Runs**
- Run K-Means multiple times
- Select clustering with lowest SSE
- Computationally expensive but effective

**Solution 2: Hierarchical Pre-Clustering**
- Use hierarchical clustering on sample
- Identify natural cluster structure
- Use results as initial centroids

**Solution 3: K-Means++ Initialization**
- Choose first centroid randomly
- For each subsequent centroid:
  - Choose point with probability ∝ D(x)²
  - D(x) = distance to nearest chosen centroid
- Spreads out initial centroids

**Solution 4: Domain Knowledge**
- Use expert knowledge about natural clusters
- Place centroids in reasonable initial positions

**Solution 5: Bisecting K-Means**
- Hierarchical variant less sensitive to initialization
- Builds clusters incrementally
- More robust results

## Bisecting K-Means

### What is Bisecting K-Means?

**Bisecting K-Means** = Hybrid approach combining:
- **Hierarchical clustering** (top-down structure)
- **K-Means clustering** (efficiency)

### Why Bisecting K-Means?

✅ **Initialization robust:** Not sensitive to random initial centroids  
✅ **Avoids local minima:** Better than pure K-Means  
✅ **Produces hierarchy:** Can choose final K by cutting tree  
✅ **Produces good clusters:** Often outperforms standard K-Means  

### Algorithm Steps

**Step 1:** Start with single cluster containing all data points

**Step 2:** Using K-Means with K=2, split cluster into 2 sub-clusters

**Step 3:** Calculate SSE for each cluster

**Step 4:** Select cluster with highest SSE

**Step 5:** Split selected cluster into 2 sub-clusters using K-Means

**Step 6:** Repeat steps 3-5 until K clusters obtained

### Pseudocode

```
procedure BISECTING_KMEANS(data_points, K):
    clusters ← [all data points as single cluster]
    
    while number of clusters < K:
        // Select cluster with highest SSE
        C_split ← cluster with max SSE from clusters
        
        // Bisect (split into 2) using K-Means
        C_1, C_2 ← KMEANS(C_split, K=2)
        
        // Replace original with two new clusters
        clusters ← clusters - {C_split} + {C_1, C_2}
    
    return clusters
```

### Bisecting K-Means Illustration

```
Step 1:  [All data]
              │

Step 2:  [Cluster A] [Cluster B]
            │
Step 3:  Split A (highest SSE):
         [A1] [A2] [B]
            │
Step 4:  Split A2:
         [A1] [A2a] [A2b] [B]
            │
Step 5:  K=4 clusters obtained
         Final result:
         [A1], [A2a], [A2b], [B]
```

### Advantages over K-Means

| Aspect | K-Means | Bisecting K-Means |
|--------|---------|-------------------|
| **Initialization** | Random, can be poor | Hierarchical, more stable |
| **Local minima** | May get stuck | Better avoidance |
| **Robustness** | Variable | More reliable |
| **Cluster quality** | Depends on K, init | Consistently good |
| **Final K choice** | Must pre-specify | Can choose by cutting |

## K-Means as Special Case of EM

### Connection to EM Algorithm

**K-Means is special case of Expectation-Maximization (EM) applied to Gaussian Mixture Models (GMM)**

### Relationship

**Standard EM for GMM:**
- **E-step:** Calculate soft responsibility (probability of cluster membership)
- **M-step:** Update parameters (means, covariances, mixing coefficients)
- **Result:** Soft assignments, probabilistic clustering

**K-Means as Hard EM:**
- **E-step:** Assign each point to **single best cluster** (hard assignment)
- **M-step:** Update centroid
- **Result:** Hard assignments, deterministic clustering

### Key Differences

| Aspect | GMM/EM | K-Means |
|--------|--------|---------|
| **Assignments** | Soft (probabilities) | Hard (binary) |
| **Assumption** | Gaussian distributions | Distance-based |
| **Uncertainty** | Captured | Not captured |
| **Mathematical** | Probabilistic | Geometric |
| **Parameters** | μ, Σ, π | Only centroid |

### Mathematical Connection

**GMM with spherical covariances:**
```
All Σₖ = σ²I (identity matrix × variance)
If σ² very small → Hard assignments
GMM effectively becomes K-Means
```

### Implication

- K-Means optimizes simplified likelihood
- EM provides richer probabilistic framework
- K-Means good for efficiency, EM for uncertainty quantification

## Key Takeaways

- **K-Means Algorithm:** Partitional clustering minimizing within-cluster SSE
- **Three Steps:** Initialization → Assignment → Update (repeat until convergence)
- **Convergence Guaranteed:** Always converges (but to local optimum)
- **SSE Metric:** Measures clustering quality, decreases monotonically
- **Elbow Method:** Choose K by finding "elbow" in SSE vs K curve
- **Limitations:** Struggles with different sizes, densities, non-spherical shapes; sensitive to outliers and initialization
- **Bisecting K-Means:** Hierarchical variant, more robust to initialization issues
- **K-Means ++ :** Better initialization strategy
- **Special Case of EM:** K-Means is hard EM for GMMs
