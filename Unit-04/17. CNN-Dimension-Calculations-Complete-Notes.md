## CNN Dimension Calculation Formulas

### Core Formula

For a convolutional layer:

```
Output_Height = ⌊(Input_Height - Filter_Height + 2×Padding) / Stride⌋ + 1
Output_Width = ⌊(Input_Width - Filter_Width + 2×Padding) / Stride⌋ + 1
Output_Channels = Number_of_Filters
```

### Pooling Formula

```
Output_Height = ⌊(Input_Height - Pool_Filter_Height) / Stride⌋ + 1
Output_Width = ⌊(Input_Width - Pool_Filter_Width) / Stride⌋ + 1
Output_Channels = Input_Channels (unchanged)
```

### Parameter Calculation

**For Convolutional Layer:**
```
Parameters = (Filter_Height × Filter_Width × Input_Channels × Number_of_Filters) + Number_of_Filters
           = (f × f × c × k) + k
           (weights + biases)
```

**For Fully Connected Layer:**
```
Parameters = Input_Size × Output_Size + Output_Size
           (weights + biases)
```

**For Pooling Layer:**
```
Parameters = 0 (No learnable parameters)
```

## AlexNet Architecture

### Overview

**AlexNet** is a landmark architecture designed by Alex Krizhevsky, Ilya Sutskever, and Geoffrey Hinton.

**Achievement:** Won ImageNet 2012 competition decisively
**Significance:** Sparked the deep learning revolution

### Overall Architecture

```
Input: 227×227×3
  ↓
Conv1: 11×11, stride=4 → 55×55×96
  ↓
MaxPool1: 3×3, stride=2 → 27×27×96
  ↓
Conv2: 5×5, padding=same → 27×27×256
  ↓
MaxPool2: 3×3, stride=2 → 13×13×256
  ↓
Conv3: 3×3, padding=same → 13×13×384
  ↓
Conv4: 3×3, padding=same → 13×13×384
  ↓
Conv5: 3×3, padding=same → 13×13×256
  ↓
MaxPool3: 3×3, stride=2 → 6×6×256
  ↓
Flatten: 6×6×256 = 9216
  ↓
FC1: 9216 → 4096
  ↓
FC2: 4096 → 4096
  ↓
FC3: 4096 → 1000 (output classes)
  ↓
Softmax → 1000 classes
```

## AlexNet Complete Walkthrough

### Conv1: Input to First Convolution

**Parameters:**
- Input: 227×227×3
- Filter: 11×11
- Stride: 4
- Padding: 0 (valid)
- Number of filters: 96

**Calculation:**
```
Output_Height = ⌊(227 - 11 + 0) / 4⌋ + 1 = ⌊216 / 4⌋ + 1 = 54 + 1 = 55
Output_Width = ⌊(227 - 11 + 0) / 4⌋ + 1 = 55
Output_Channels = 96

Output shape: 55×55×96
```

**Parameters:**
```
Conv1 parameters = (11 × 11 × 3 × 96) + 96
                 = 34,848 + 96
                 = 34,944 parameters
```

### MaxPool1: First Pooling

**Parameters:**
- Input: 55×55×96
- Filter: 3×3
- Stride: 2

**Calculation:**
```
Output_Height = ⌊(55 - 3) / 2⌋ + 1 = ⌊52 / 2⌋ + 1 = 26 + 1 = 27
Output_Width = ⌊(55 - 3) / 2⌋ + 1 = 27
Output_Channels = 96 (unchanged)

Output shape: 27×27×96
```

**Parameters:** 0 (no learnable weights)

### Conv2: Second Convolution

**Parameters:**
- Input: 27×27×96
- Filter: 5×5
- Padding: same (maintains spatial dimensions)
- Stride: 1
- Number of filters: 256

**For padding = same with stride 1:**
```
Required padding = (f - 1) / 2 = (5 - 1) / 2 = 2
```

**Calculation:**
```
Output_Height = ⌊(27 - 5 + 2×2) / 1⌋ + 1 = ⌊(27 - 5 + 4) / 1⌋ + 1 = 26 + 1 = 27
Output_Width = 27
Output_Channels = 256

Output shape: 27×27×256
```

**Parameters:**
```
Conv2 parameters = (5 × 5 × 96 × 256) + 256
                 = 614,400 + 256
                 = 614,656 parameters
```

### MaxPool2: Second Pooling

**Parameters:**
- Input: 27×27×256
- Filter: 3×3
- Stride: 2

**Calculation:**
```
Output_Height = ⌊(27 - 3) / 2⌋ + 1 = ⌊24 / 2⌋ + 1 = 12 + 1 = 13
Output_Width = 13
Output_Channels = 256

Output shape: 13×13×256
```

**Parameters:** 0

### Conv3, Conv4, Conv5: Deeper Convolutions

**Conv3:**
- Input: 13×13×256
- Filter: 3×3, padding=same, stride=1, filters=384
- Output: 13×13×384
- Parameters: (3 × 3 × 256 × 384) + 384 = 884,736 + 384 = 885,120

**Conv4:**
- Input: 13×13×384
- Filter: 3×3, padding=same, stride=1, filters=384
- Output: 13×13×384
- Parameters: (3 × 3 × 384 × 384) + 384 = 1,327,104 + 384 = 1,327,488

**Conv5:**
- Input: 13×13×384
- Filter: 3×3, padding=same, stride=1, filters=256
- Output: 13×13×256
- Parameters: (3 × 3 × 384 × 256) + 256 = 884,736 + 256 = 884,992

### MaxPool3: Third Pooling

**Parameters:**
- Input: 13×13×256
- Filter: 3×3
- Stride: 2

**Calculation:**
```
Output_Height = ⌊(13 - 3) / 2⌋ + 1 = ⌊10 / 2⌋ + 1 = 5 + 1 = 6
Output_Width = 6
Output_Channels = 256

Output shape: 6×6×256
```

**Parameters:** 0

### Flatten: Convert to Vector

**Calculation:**
```
Flattened size = 6 × 6 × 256 = 9,216
Shape: 9216×1 (column vector)
```

### FC1: First Fully Connected

**Parameters:**
- Input: 9,216
- Output: 4,096

**Calculation:**
```
FC1 parameters = (9,216 × 4,096) + 4,096
               = 37,748,736 + 4,096
               = 37,752,832 parameters
```

### FC2: Second Fully Connected

**Parameters:**
- Input: 4,096
- Output: 4,096

**Calculation:**
```
FC2 parameters = (4,096 × 4,096) + 4,096
               = 16,777,216 + 4,096
               = 16,781,312 parameters
```

### FC3/Output: Classification

**Parameters:**
- Input: 4,096
- Output: 1,000

**Calculation:**
```
FC3 parameters = (4,096 × 1,000) + 1,000
               = 4,096,000 + 1,000
               = 4,097,000 parameters
```

### AlexNet Total Parameters

```
Conv1:    34,944
Conv2:    614,656
Conv3:    885,120
Conv4:    1,327,488
Conv5:    884,992
FC1:      37,752,832
FC2:      16,781,312
FC3:      4,097,000

TOTAL:    62,378,344 parameters
```

### Key Observations

✅ **Most parameters in FC layers** (60,631,144 / 62,378,344 ≈ 97%)
✅ **Convolution layers compact** (1,746,200 parameters)
✅ **Pooling layers free** (0 parameters)
✅ **Dimensions shrink progressively** (227→55→27→13→6)
✅ **Channels increase** (3→96→256→384→256)

## LeNet-5 Architecture

### Overview

**LeNet-5** is a classic CNN for handwritten digit recognition

**Achievement:** Successfully recognized handwritten digits
**Historical Significance:** First practical CNN implementation
**Simplicity:** Easy to understand and implement

### Architecture for Digit Recognition

```
Input: 32×32×3 (grayscale digit image)
  ↓
Conv1: 5×5, stride=1, filters=6, padding=0 → 28×28×6
  ↓
MaxPool1: 2×2, stride=2 → 14×14×6
  ↓
Conv2: 5×5, stride=1, filters=16, padding=0 → 10×10×16
  ↓
MaxPool2: 2×2, stride=2 → 5×5×16
  ↓
Flatten: 5×5×16 = 400
  ↓
FC1: 400 → 120
  ↓
FC2: 120 → 84
  ↓
Softmax: 84 → 10 (digits 0-9)
```

## Parameter Calculation Methods

### Method 1: Step-by-Step

1. Calculate output dimensions after each layer
2. For each Conv/FC layer, calculate (input_size × output_size × output_channels) + biases
3. Sum all parameters

### Method 2: Table-Based

Create table with columns:
- Layer name
- Input shape
- Output shape
- Weights calculation
- Bias calculation
- Total parameters

### Common Mistakes to Avoid

❌ **Forgetting biases** - Always add bias parameters  
❌ **Wrong input channels** - Must match previous layer's output channels  
❌ **Dimension mismatch** - Verify formula application  
❌ **Pooling parameters** - Pooling layers have 0 learnable parameters

## Deep Network Characteristics

### Dimension Shrinkage

**Pattern observed in AlexNet and LeNet:**

```
Spatial dimensions decrease as we go deeper:
227 → 55 → 27 → 13 → 6 (AlexNet)
32 → 28 → 14 → 10 → 5 (LeNet)

Channels increase:
3 → 96 → 256 → 384 → 256 (AlexNet)
3 → 8 → 16 (LeNet)
```

**Why this pattern?**
- Convolution without padding reduces size
- Pooling reduces size by stride factor
- More filters capture more features
- Deeper layers learn more complex patterns

### Information Compression

```
AlexNet:
Input: 227×227×3 = 154,587 values
After Conv1+Pool1: 27×27×96 = 69,984 values
After Conv5+Pool5: 6×6×256 = 9,216 values
After Flatten+FC1: 4,096 values

Compression ratio: 154,587 / 4,096 ≈ 38× compression
```

### Parameter Distribution

**AlexNet:**
- Convolution layers: 1,746,200 (2.8%)
- Fully connected layers: 60,631,144 (97.2%)

**Key insight:** FC layers are parameter-heavy, Conv layers are efficient

## Practical Considerations

### Choosing Architecture

**Factors:**
- Input image size
- Number of classes
- Computational budget
- Available training data
- Inference speed requirements

### Common Starting Points

- **Small images (32×32):** LeNet-like architecture
- **Medium images (224×224):** VGGNet or ResNet
- **Large images (>400×400):** Deeper networks or multi-scale approaches
- **Mobile/Edge:** MobileNet, SqueezeNet

### Training Considerations

- **Gradient flow:** Very deep networks need skip connections
- **Overfitting:** Larger networks overfit on small datasets
- **Computational cost:** More parameters = longer training
- **Memory:** Batch size limited by GPU/RAM

## Common Pitfalls

### 1. Incorrect Dimension Calculation

**Wrong:**
```
Input 224×224, Filter 3×3, stride 1
Output = 224 - 3 = 221 (WRONG - forgot +1)
```

**Correct:**
```
Output = (224 - 3) / 1 + 1 = 222
```

### 2. Forgetting Padding in Formula

**Wrong:**
```
Output = (224 - 3 + 1) = 222 (forgot padding term)
```

**Correct:**
```
Output = (224 - 3 + 2×1) / 1 + 1 = 224 (with padding=1)
```

### 3. Channel Mismatch

**Wrong:**
```
Input: 32×32×64
Filter: 3×3×32 (should match 64, not 32!)
```

**Correct:**
```
Filter: 3×3×64 (must match input channels)
```

### 4. Pooling With Learnable Parameters

**Wrong:**
```
MaxPool layer has 500,000 parameters? NO!
```

**Correct:**
```
Pooling layer has 0 learnable parameters
```

### 5. Off-by-One Errors

**Always use floor operation:**
```
Output = ⌊(Input - Filter + 2×Padding) / Stride⌋ + 1

Not:
Output = (Input - Filter + 2×Padding) / Stride
```

### Problem 1: Dimension Calculation

Given:
- Input: 64×64×3
- Conv filter: 5×5, stride=2, padding=0, 32 filters
- MaxPool: 2×2, stride=2

Calculate:
1. Conv output dimensions
2. MaxPool output dimensions
3. Number of Conv parameters

**Solution:**
```
Conv output: (64-5+0)/2 + 1 = 30.5 → ⌊30.5⌋ = 30 → 30×30×32
Parameters: 5×5×3×32 + 32 = 2,400 + 32 = 2,432

MaxPool output: (30-2)/2 + 1 = 15×15×32
Parameters: 0
```
