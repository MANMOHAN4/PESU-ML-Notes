## Transformer Architecture Overview

### High-Level Structure

**Transformers replace RNNs with attention mechanisms**

```
Input Sequence → Positional Encoding → Encoder Stack → Decoder Stack → Output
                       ↑                    ↑              ↑
                   Add position info   Multi-head      Multi-head
                                       attention       attention
```

### Key Components

**Encoder:**
- Stack of identical layers (typically 6)
- Self-attention layer
- Feed-forward network
- Layer normalization + residual connections

**Decoder:**
- Stack of identical layers (typically 6)
- Masked self-attention (can't look ahead)
- Encoder-decoder attention
- Feed-forward network
- Layer normalization + residual connections

### Fundamental Principle

**"Attention is All You Need"**
- Replaces recurrent connections with attention
- Processes entire sequence in parallel (vs sequential RNN)
- More efficient computation
- Better long-range dependencies

## Why Transformers

### Problems with RNNs

**Sequential Processing:**
- Processes one token at a time
- Can't parallelize computation
- Slow training and inference

**Vanishing/Exploding Gradients:**
- Difficulty learning long-term dependencies
- Even with LSTM/GRU, limited range

**Memory Limitations:**
- Must pass hidden state sequentially
- Information gets diluted over long sequences

### Transformer Advantages

✅ **Parallelizable:** Process entire sequence at once
✅ **Better long-range:** Attention can look at any position
✅ **Scalable:** Scales better with sequence length
✅ **Efficient:** Can use larger batches
✅ **State-of-the-art:** Powers modern NLP models

## Positional Encoding

### Why Needed

**Problem:** Transformers don't process words sequentially like RNNs

**Challenge:** Need to communicate word order to the model

**Solution:** Positional encoding adds position information to embeddings

### High-Level Idea

**For each word:**
1. Get word embedding (meaning)
2. Calculate positional encoding (position)
3. Add them together
4. Result: Combined meaning + position

### Intuition

```
"dog" + "sat" + "mat"
 ↓      ↓      ↓
Add positional info to show order:
"dog"(pos=1) + "sat"(pos=2) + "mat"(pos=3)
↓
Model understands sequence order
```

### Design Principle

**Why sinusoids?**
- Creates unique vectors for each position
- Generalizes to sequences longer than training
- Different frequencies capture different distances
- Can learn relative positions

## Encoder Architecture

### Overall Structure

```
Input Embeddings + Positional Encoding
        ↓
  [ENCODER LAYER 1]
  - Multi-Head Attention
  - Layer Norm + Residual
  - Feed-Forward Network
  - Layer Norm + Residual
        ↓
  [ENCODER LAYER 2]
  - (same structure)
        ↓
  ... (6 layers total)
        ↓
  Encoder Output
```

### Layer Components

**1. Self-Attention Layer:**
- Lets encoder look at all words in input sentence
- Each word attends to all other words
- Calculates which parts are relevant

**2. Feed-Forward Layer:**
- Simple fully connected network
- Applied independently to each position
- Same network for all positions
- Creates richer representations

**3. Normalization & Residual:**
- Layer normalization for stability
- Residual connections for gradient flow
- Add input to output: output = input + sublayer(input)

### Information Flow

```
[Input]
  ↓
[Multi-Head Attention] → produces attended representations
  ↓
[Add & Normalize] → residual connection + layer norm
  ↓
[Feed-Forward] → position-wise transformation
  ↓
[Add & Normalize] → residual connection + layer norm
  ↓
[Output to Next Layer]
```

## Decoder Architecture

### Overall Structure

```
Output Embeddings + Positional Encoding
        ↓
  [DECODER LAYER 1]
  - Masked Multi-Head Attention (can't look ahead)
  - Layer Norm + Residual
  - Encoder-Decoder Attention
  - Layer Norm + Residual
  - Feed-Forward Network
  - Layer Norm + Residual
        ↓
  [DECODER LAYER 2]
  - (same structure)
        ↓
  ... (6 layers total)
        ↓
  [Linear Layer] → projects to vocabulary size
  ↓
  [Softmax] → probabilities
  ↓
  [Output Token]
```

### Key Difference: Masked Attention

**Why masked?**
- Decoder generates output one token at a time
- Can't look at future tokens (haven't generated yet)
- Would be "cheating" to look ahead

**How masking works:**
- Block attention to positions in future
- Add -∞ to future position scores
- After softmax: 0 probability for masked positions

### Three Attention Mechanisms

**1. Masked Self-Attention:**
- Decoder looks at its own previous tokens
- Can't see future tokens

**2. Encoder-Decoder Attention:**
- Queries from decoder
- Keys and values from encoder
- Decoder focuses on relevant encoder information

**3. Encoder Self-Attention:**
- Encoder looking at encoder input
- No masking (can see all input)

## Self-Attention Mechanism

### Conceptual Understanding

**Question:** When processing a word, which other words should I focus on?

**Example:**
```
Sentence: "The animal didn't cross the street because it was too tired"
When processing: "it"

Which word does "it" refer to?
Answer: "animal" (not "street")

Self-attention learns to make this connection
```

### How Self-Attention Works

**1. Each word attends to all other words**
- Calculates relevance to every word in sentence
- Results in attention weights

**2. Weights guide feature combination**
- High weight: word is relevant, combine heavily
- Low weight: word is irrelevant, ignore mostly

**3. Creates richer representations**
- Each word's representation blends context information
- Different meanings captured in different attention heads

---

## Self-Attention Calculation

### Step 1: Compute Q, K, V Matrices

**For each word embedding, create:**
- **Query (Q):** "What am I looking for?"
- **Key (K):** "What information do I have?"
- **Value (V):** "What should I output?"

**Process:**
```
For input embedding matrix X (n_words × d_model):
Q = X × WQ
K = X × WK
V = X × WV

Where WQ, WK, WV are learned weight matrices
```

### Step 2: Calculate Attention Scores

**Score matrix:** How much does query relate to each key?

```
Scores = Q × K^T / √(d_k)

Where:
- Q × K^T: dot product (similarity)
- √(d_k): scaling factor for stability
- Result: n_words × n_words matrix
```

### Step 3: Apply Softmax

**Convert scores to probabilities:**

```
Attention_weights = softmax(Scores)

Properties:
- All weights sum to 1
- Between 0 and 1
- Emphasizes highest scores
```

### Step 4: Apply to Values

**Weighted combination of values:**

```
Output = Attention_weights × V

For each word:
- Sum all values weighted by attention
- Higher attention weight → more influence
- Creates context-aware representation
```

### Example Calculation

**Simplified example:** 2 words

```
Words: ["Thinking", "Machines"]

Step 1: Create Q, K, V
Q = [0.2, 0.1]ᵀ (what each word is looking for)
K = [0.3, 0.4]ᵀ (what each word offers)
V = [0.5, 0.6]ᵀ (values to combine)

Step 2: Compute scores
Score(word1→word1) = 0.2 × 0.3 / √64 = 0.0075
Score(word1→word2) = 0.2 × 0.4 / √64 = 0.01
Score(word2→word1) = 0.1 × 0.3 / √64 = 0.00375
Score(word2→word2) = 0.1 × 0.4 / √64 = 0.005

Step 3: Softmax
Weights(word1) ≈ [0.48, 0.52]
Weights(word2) ≈ [0.49, 0.51]

Step 4: Apply to values
Output(word1) = 0.48×0.5 + 0.52×0.6 = 0.552
Output(word2) = 0.49×0.5 + 0.51×0.6 = 0.555
```

## Multi-Head Attention

### Concept

**Instead of one attention mechanism, use multiple in parallel**

```
Single Head:
Input → Attention → Output

Multi-Head (8 heads):
Input → [Head1, Head2, Head3, ..., Head8] → Concatenate → Linear → Output
        Each head processes independently
```

### Why Multiple Heads?

✅ **Attend to different parts of space**
- Head 1: Focus on subject
- Head 2: Focus on verb
- Head 3: Focus on objects

✅ **Attend to different representation subspaces**
- Head 1: Syntactic features
- Head 2: Semantic features
- Head 3: Position information

✅ **More expressive representation**
- Richer understanding of relationships
- Better feature extraction

### Computational Process

**For each head (independently):**

```
1. Project Q, K, V to smaller dimensions
   Q_i = X × WQ_i
   K_i = X × WK_i
   V_i = X × WV_i
   
   (d_model → d_k where d_k = d_model / n_heads)

2. Apply attention mechanism
   head_i = Attention(Q_i, K_i, V_i)

3. Results: n_heads different representations
```

**Combine all heads:**

```
1. Concatenate all head outputs
   Z = [head_1; head_2; ...; head_8]  (restore to d_model dimensions)

2. Linear projection
   MultiHead = Z × WO
   
   (Learn how to optimally combine head information)
```

### Example: 8 Heads

```
Input (d_model = 512)
    ↓
    ├→ Head 1 (d_k = 64)
    ├→ Head 2 (d_k = 64)
    ├→ Head 3 (d_k = 64)
    ├→ Head 4 (d_k = 64)
    ├→ Head 5 (d_k = 64)
    ├→ Head 6 (d_k = 64)
    ├→ Head 7 (d_k = 64)
    └→ Head 8 (d_k = 64)
    ↓
Concatenate all → 8 × 64 = 512
    ↓
Linear projection → Output (512)
```

## Encoder-Decoder Attention

### Purpose

**Allow decoder to focus on relevant encoder information**

```
Queries come from decoder
Keys and Values come from encoder

Question: "What from the input should I focus on?"
```

### How It Works

```
Decoder Query (Q):
"What information do I need?"
Generated from decoder's previous layer

Encoder Keys and Values (K, V):
"What information is available?"
From encoder's final output

Process:
Attention(Q_decoder, K_encoder, V_encoder)
= how decoder should attend to encoder
```

### Example: Machine Translation

```
Input (English): "I am a student"
        ↓
    [ENCODER] → learns representation of English
        ↓
Output (French): "Je suis étudiant"
        ↓
    [DECODER]
    When generating "Je": 
    - Looks at "I" and "am" in encoder
    - Focuses on relevant English words
    
    When generating "suis":
    - Looks at all English words
    - Focuses on "am" (being verb)
    
    When generating "étudiant":
    - Focuses on "student"
```

## Masked Multi-Head Attention

### The Masking Problem

**Why needed:**
- Decoder generates output one token at a time
- When predicting position i, haven't generated positions > i
- Can't look at future tokens (would be cheating)

**Example - Predicting "am":**
```
Generated so far: "Je"
Predicting: "am"
Available: ["Je"]
NOT available: everything after

Must mask: "Je suis étudiant"
Only use: "Je"
```

### How Masking Works

**Add -∞ to future positions before softmax:**

```
Step 1: Calculate attention scores
[s1  s2  s3]
[s4  s5  s6]
[s7  s8  s9]

Step 2: Apply look-ahead mask (set future to -∞)
[s1   -∞  -∞]
[s4  s5   -∞]
[s7  s8   s9]

Step 3: Apply softmax
[e^s1/Z   0     0  ]
[e^s4/(e^s4+e^s5+e^s6)  e^s5/(e^s4+e^s5+e^s6)  0]
[e^s7/Z   e^s8/Z   e^s9/Z]

Result: Each position only attends to itself and earlier positions
```

## Feed-Forward Networks

### Architecture

**For each position independently:**

```
Input → Dense(d_ff, ReLU) → Dense(d_model) → Output

Where:
d_model = 512 (input dimension)
d_ff = 2048 (hidden dimension, typically 4× larger)
```

### Mathematical Form

```
FFN(x) = max(0, xW₁ + b₁)W₂ + b₂

Or with ReLU:
FFN(x) = ReLU(xW₁ + b₁)W₂ + b₂
```

### Applied Position-Wise

**Same FFN applied to all positions:**
- Position 1: passes through same FFN
- Position 2: passes through same FFN
- ...and so on

**But weights learned globally:**
- Allows sharing of representations
- Efficient parameter count

### Purpose

- Adds non-linearity
- Projects to higher dimension (captures interactions)
- Projects back to original dimension
- Acts as position-wise transformation

## Output and Softmax Layer

### Linear Layer

**Purpose:** Project decoder output to vocabulary

```
Decoder Output: (seq_len, d_model) = (n, 512)
        ↓
Linear Layer: (512) → (vocab_size)
        ↓
Logits: (seq_len, vocab_size) = (n, 10000)

Where vocab_size = size of vocabulary (e.g., 10,000 words)
```

### Softmax Layer

**Purpose:** Convert logits to probabilities

```
Input: Logits [l₁, l₂, ..., lₙ]
        ↓
Softmax: P(word_i) = e^(l_i) / Σⱼ e^(l_j)
        ↓
Output: Probabilities [p₁, p₂, ..., pₙ]

Properties:
- All probabilities between 0 and 1
- Sum to 1
- Valid probability distribution
```

### Output Selection

**Generate next token:**

```
1. Get logits from linear layer
2. Apply softmax to get probabilities
3. Select word with highest probability
4. Add to output sequence
5. Feed back as decoder input for next step
```

### Example

```
Logits: [2.1, 0.5, 3.2, 1.1, 0.3]
        ↓
Softmax:
e^2.1 ≈ 8.17
e^0.5 ≈ 1.65
e^3.2 ≈ 24.53
e^1.1 ≈ 3.00
e^0.3 ≈ 1.35

Sum ≈ 38.7

Probabilities: [0.21, 0.04, 0.63, 0.08, 0.03]
        ↓
Highest: word 3 (63% probability)
        ↓
Select: word 3
```

## Complete Transformer Flow

### End-to-End Process

**Input Sentence → Translation Output**

```
INPUT (English): "I am a student"
        ↓
1. EMBEDDING & POSITIONAL ENCODING
   - Each word gets embedding
   - Add positional information
   - Result: Embeddings with position info
        ↓
2. ENCODER
   - 6 encoder layers
   - Each layer: Self-attention + FFN
   - Learn representation of input
   - Output: Encoded representation
        ↓
3. DECODER (autoregressive, one word at a time)
   
   Step 1: Generate first word
   - Input: <START> token
   - Masked self-attention: attend to self
   - Encoder-decoder attention: attend to encoder
   - FFN: process
   - Linear + Softmax: predict "Je"
   
   Step 2: Generate second word
   - Input: <START> "Je"
   - Masked self-attention: attend to <START> and "Je"
   - Encoder-decoder attention: focus on English input
   - FFN: process
   - Linear + Softmax: predict "suis"
   
   Step 3: Generate third word
   - Input: <START> "Je" "suis"
   - ... same process ...
   - Predict: "étudiant"
   
   Step 4: Stop when <END> token generated
        ↓
OUTPUT (French): "Je suis étudiant"
```

### Decoding Strategies

**Greedy Decoding:**
- Always pick highest probability word
- Fast but may miss better sequences

**Beam Search:**
- Track multiple candidate sequences
- Keep top k options at each step
- More quality but slower

**Temperature Sampling:**
- Control randomness
- Higher temp: more random
- Lower temp: more greedy

## Positional Encoding Mathematical Details

### Formula

**For position k and dimension i:**

```
PE(k, 2i) = sin(k / 10000^(2i/d))
PE(k, 2i+1) = cos(k / 10000^(2i/d))

Where:
- k = position in sequence (0, 1, 2, ...)
- i = dimension index (0, 1, 2, ..., d/2)
- d = total embedding dimension
- 10000 is the base (fixed by authors)
```

### Intuition

**Why sine and cosine?**
- Different frequencies for different dimensions
- Low dimensions: slow oscillation (captures long distances)
- High dimensions: fast oscillation (captures short distances)
- Periodic pattern: generalizes to unseen sequence lengths

### Example

**Phrase:** "I am a robot"
**n = 100, d = 4**

```
Position k=0 ("I"):
PE(0,0) = sin(0/1) = 0
PE(0,1) = cos(0/1) = 1
PE(0,2) = sin(0/10) = 0
PE(0,3) = cos(0/10) = 1
Result: [0, 1, 0, 1]

Position k=1 ("am"):
PE(1,0) = sin(1/1) = 0.84
PE(1,1) = cos(1/1) = 0.54
PE(1,2) = sin(1/10) = 0.10
PE(1,3) = cos(1/10) = 1.0
Result: [0.84, 0.54, 0.10, 1.0]

Position k=2 ("a"):
PE(2,0) = sin(2/1) = 0.91
PE(2,1) = cos(2/1) = -0.42
PE(2,2) = sin(2/10) = 0.20
PE(2,3) = cos(2/10) = 0.98
Result: [0.91, -0.42, 0.20, 0.98]

Position k=3 ("robot"):
PE(3,0) = sin(3/1) = 0.14
PE(3,1) = cos(3/1) = -0.99
PE(3,2) = sin(3/10) = 0.30
PE(3,3) = cos(3/10) = 0.96
Result: [0.14, -0.99, 0.30, 0.96]
```

### Adding to Embeddings

```
For each word:
Final_embedding = word_embedding + positional_encoding

Effect:
- Same word in different positions gets different embedding
- Nearby words have similar encodings
- Far words have different encodings
- Model learns relative positions
```

## Query-Key-Value Mechanism

### Conceptual Understanding

**Analogy: Database Lookup**

```
Query: "What am I looking for?"
Key: "What information do I contain?"
Value: "What should I return?"

Similarity(Query, Key) tells relevance
If high similarity → return corresponding Value
```

### Mathematical Process

**1. Initialize Q, K, V:**
```
Q = Input × WQ
K = Input × WK
V = Input × WV
```

**2. Compute compatibility:**
```
Score(Q, K) = Q · K / √(d_k)
```

**3. Normalize (Softmax):**
```
Weight(Q, K) = softmax(Score)
```

**4. Apply to values:**
```
Output = Weight × V
```

### Why Three Matrices?

**Query (WQ):**
- Projects input to "what I'm looking for"
- Represents information need
- Same for all query operations

**Key (WK):**
- Projects input to "what I can offer"
- Represents content being searched
- Same for all key operations

**Value (WV):**
- Projects input to "what I will output"
- Represents information to aggregate
- Same for all value operations

**Separate matrices:**
- Learn different projections for each role
- More expressive than single projection
- Allow richer relationships

## Key Takeaways

- **Transformers:** Attention-based architecture replacing RNNs
- **Positional Encoding:** Communicates word order using sinusoids
- **Self-Attention:** Each word attends to all other words
- **Multi-Head Attention:** Multiple attention mechanisms in parallel
- **Encoder:** Processes input sentence
- **Decoder:** Generates output one token at a time
- **Masked Attention:** Prevents looking at future tokens
- **Query-Key-Value:** Mechanism for selective attention
- **Scalability:** Parallel processing enables large-scale training
- **State-of-the-art:** Foundation for GPT, BERT, T5, and modern LLMs
