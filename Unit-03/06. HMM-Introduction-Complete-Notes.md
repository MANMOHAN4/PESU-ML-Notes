## From Markov Chain to HMM

### Review: Markov Chain
In a standard Markov Chain:
- **All states are visible** to the observer
- We directly observe state transitions
- Examples: Weather states directly observable (Sunny, Rainy, Cloudy)

### Limitation of Markov Chain
- Some internal states cannot be directly observed
- We only see **effects or manifestations** of hidden states
- Example: Patient's actual disease state (hidden) vs. symptoms observed (visible)

### Solution: Hidden Markov Models (HMM)
Extend Markov chains by:
1. Making internal states **hidden** (not directly observable)
2. Adding **observations** that are generated/emitted by hidden states
3. Maintaining temporal dependencies through hidden state transitions

---

## Key Distinction: States vs Observations

### State (Hidden)
- **Internal condition** of the system
- **Not directly observable**
- Evolves over time according to transition probabilities
- Examples: Patient's disease state, speaker's emotion, weather system pattern

### Observation (Visible)
- **Manifestation or effect** of the hidden state
- **Directly observable and measurable**
- Generated/emitted by the hidden state
- Examples: Patient's symptoms, speaker's voice pattern, barometer reading

### Relationship
```
Hidden State → (generates/emits) → Observation
```

### Real-World Example: Patient Health

**Hidden States (not directly observable):**
- Healthy, Mild Illness, Severe Illness

**Observations (directly observable):**
- No Symptoms, Low Fever, High Fever, Cough, Fatigue

**Process:**
```
At time t=1: Hidden state = Healthy → Emits observation = No Symptoms
At time t=2: Hidden state transitions to Mild → Emits observation = Low Fever
At time t=3: Hidden state transitions to Severe → Emits observation = High Fever
```

## Hidden Markov Model Definition

### Formal Definition
**A Hidden Markov Model is a Markov process that at each time step generates a symbol from some alphabet Σ, according to emission probability that depends on the current hidden state.**

### Key Insight
- HMM uses two-layer structure: Hidden states (internal) and observations (external)
- Each hidden state can generate multiple different observations with different probabilities
- This captures realistic stochasticity in observations

## HMM Parameters

### Complete HMM Characterization: λ(π, A, B)

An HMM is fully defined by three components:

### 1. π: Initial Distribution

**Definition:** Probability that HMM starts with hidden state j

```
πⱼ = P(q₁ = j)
```

**Properties:**
- One value for each hidden state
- All values sum to 1
- Represents starting state preferences

### 2. A: Transition Matrix

**Definition:** Probability of transitioning from hidden state i to hidden state j

```
aᵢⱼ = P(qₜ₊₁ = j | qₜ = i)
```

**Properties:**
- N × N matrix (N = number of hidden states)
- Transition between hidden states (not affected by observations)
- Row sums equal 1
- Same structure as Markov chain transition matrix

### 3. B: Emission Matrix

**Definition:** Probability of observing symbol oₜ when in hidden state j

```
bⱼ(oₜ) = P(oₜ = symbol | qₜ = j)
```

**Properties:**
- M rows (M = number of hidden states)
- V columns (V = size of observation alphabet)
- Each row sums to 1
- **Critical difference from Markov chains** - this is what makes states "hidden"

### Complete Parameter Set
```
λ(π, A, B) where:
- π: 1 × N vector (initial state probabilities)
- A: N × N matrix (state transition probabilities)
- B: N × V matrix (emission/observation probabilities)
- N: number of hidden states
- V: size of observation vocabulary/alphabet
```

## Understanding Emission Probabilities

### What are Emission Probabilities?

**Emission probabilities** define how hidden states produce observations. They answer:

**"What is the probability of observing symbol X given that the system is in hidden state Y?"**

### Why Different Emission Probabilities Matter

**If a hidden state has different emission probabilities for different observations:**

1. **Captures Uncertainty in Observations**
   - Same hidden state doesn't always produce same observation
   - Example: Patient with Mild Illness might have:
     - Low fever (60% probability)
     - Headache (30% probability)
     - No symptoms (10% probability)

2. **Represents Probabilistic Nature**
   - System is stochastic, not deterministic
   - Real-world observations have inherent variability

3. **Increases Model Expressiveness**
   - Can capture variability in real-world data
   - Without different probabilities, model would be too rigid

### Example: Employee Productivity Hidden States

**Hidden States:** High Productivity, Medium Productivity, Low Productivity

**Observations:** Completes report, Takes break, Attends meeting

**Emission Matrix B:**

```
                Report  Break  Meeting
High            0.7     0.1    0.2
Medium          0.5     0.2    0.3
Low             0.3     0.4    0.3
```

**Interpretation:**
- When employee is in "High Productivity" state:
  - 70% chance they complete a report
  - 10% chance they take a break
  - 20% chance they attend a meeting
- When employee is in "Low Productivity" state:
  - 30% chance they complete a report
  - 40% chance they take a break
  - 30% chance they attend a meeting

## Fundamental Assumptions in HMM

### 1. Markov Assumption

**Statement:** Future hidden state depends only on current hidden state, not on entire history

```
P(qₜ₊₁ = j | qₜ = i, ..., q₁ = i₁) = P(qₜ₊₁ = j | qₜ = i)
```

**Implication:**
- Hidden state transitions follow Markov property
- Temporal dependency limited to one step
- Simplifies computation

### 2. Output Independence Assumption

**Statement:** Observation at time t depends only on hidden state at time t, not on other observations or states

```
P(oₜ | qₜ = j, oₜ₋₁, oₜ₋₂, ..., o₁, qₜ₋₁, qₜ₋₂, ...) = P(oₜ | qₜ = j)
```

**Implication:**
- Observations are independent given hidden state
- Current observation doesn't influence future hidden states
- Only hidden states carry information forward in time

**Rationale:** Hidden states are "sufficient statistics" - they encapsulate all relevant information from past observations for predicting the future

## HMM Examples

### Example 1: Restaurant Mood HMM

**Hidden States:** Happy, Grumpy

**Observations:** Happy mood, Grumpy mood

**Parameters:**

```
Initial Distribution:
π = {2/3 (Happy), 1/3 (Grumpy)}

Transition Matrix (Hidden States):
        Happy  Grumpy
Happy  [0.8    0.2   ]
A =    
Grumpy [0.4    0.6   ]

Emission Matrix (Observations):
        Happy  Grumpy
Happy  [0.8    0.2   ]
B =    
Grumpy [0.4    0.6   ]
```

**Interpretation:**
- 80% of time, Happy state leads to Happy observation
- 40% of time, Grumpy state leads to Happy observation (stochastic emission)

### Example 2: Weather HMM

**Hidden States:** Sunny, Rainy

**Observations:** Clean, Shop, Walk

**Emission Probabilities:**
```
        Clean  Shop  Walk
Sunny  [0.6    0.3   0.1 ]
B =    
Rainy  [0.1    0.4   0.5 ]
```

**Interpretation:**
- When it's Sunny: Most likely activity is Clean (60%), then Shop (30%), less likely Walk (10%)
- When it's Rainy: Most likely activity is Walk (50%), then Shop (40%), least likely Clean (10%)

## Three Key Problems in HMM

### Problem 1: Likelihood Problem

**What:** Given observation sequence O, find likelihood P(O|λ)

**Question:** "How probable is this observation sequence given the model?"

**Use Cases:**
- Anomaly detection (unusual sequences have low likelihood)
- Model evaluation (compare different models)
- Diagnosis (typical vs. unusual patient symptom progression)

**Computational Challenge:** 
- N^T possible hidden state sequences of length T
- Brute force enumeration infeasible for large T

**Solution:** Forward/Backward algorithms (dynamic programming)

### Problem 2: Decoding Problem

**What:** Given observation sequence O, find best hidden state sequence Q*

```
Q* = argmax_Q P(Q|O, λ)
```

**Question:** "What is the most likely sequence of hidden states that generated these observations?"

**Use Cases:**
- Speech recognition (find most likely phoneme sequence)
- Part-of-speech tagging (find most likely POS sequence)
- Disease diagnosis (find most likely disease progression)
- Gesture recognition (find most likely action sequence)

**Computational Challenge:**
- Exponential number of possible sequences
- Need to find maximum among all

**Solution:** Viterbi algorithm (dynamic programming with backpointers)

### Problem 3: Learning Problem

**What:** Given observation sequences O, learn parameters λ(π, A, B)

```
λ* = argmax_λ P(O|λ)
```

**Question:** "What model parameters best explain the observed data?"

**Use Cases:**
- Training HMMs from data
- Parameter estimation from training sequences
- Adapting models to specific speakers/domains

**Computational Challenge:**
- Unknown hidden states (can't directly count transitions)
- Need to estimate from incomplete information

**Solution:** Baum-Welch algorithm (EM - Expectation Maximization)

## Summary

**Hidden Markov Models extend Markov chains by:**
1. Making states hidden (unobservable)
2. Adding observations generated by hidden states
3. Maintaining temporal dependencies through hidden state transitions

**HMM is defined by:** λ(π, A, B)
- π: initial state distribution
- A: hidden state transition probabilities
- B: observation emission probabilities

**Key Assumptions:**
1. Markov assumption (future depends on present)
2. Output independence (observation depends only on current state)

**Three main problems:**
1. Likelihood - probability of observations
2. Decoding - best hidden state sequence
3. Learning - parameter estimation from data
