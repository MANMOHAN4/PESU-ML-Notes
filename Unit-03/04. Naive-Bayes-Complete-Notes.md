## Introduction to Naive Bayes Classifier

### What is Naive Bayes?
- **Instance Representation:** Each data instance is described by a conjunction of attribute values.
- **Classes:** Data can belong to two or more classes (binary or multi-class).
- **Goal:** Use Bayesian reasoning to classify new instances based on observed attribute values.
- **Performance:** Comparable to Neural Networks and Decision Trees in many domains.

### Types of Attributes:
- **Continuous:** Use Gaussian Naive Bayes (assume features follow normal distribution).
- **Discrete Counts:** Use Multinomial Naive Bayes (word counts in documents).
- **Binary:** Use Bernoulli Naive Bayes (features with values 0 or 1).

---

## Types of Naive Bayes Classifiers
- **Gaussian:** Continuous data, assumes normal distribution per class, feature-wise.
- **Multinomial:** Discrete counts, especially text (bag of words/count vectors).
- **Bernoulli:** Binary features (0/1), e.g., presence/absence of word in document.

## Mathematical Foundation and Assumptions

### Most Probable Classification
Given new instance X_new with d attributes:
- Use Bayes to compute the most probable class

### Bayes Rule for Classification
```
P(Vj | X) ∝ P(X | Vj) · P(Vj)
```
- Compute for all possible classes
- Assign instance to the class with maximum posterior probability

### Conditional Independence Assumption
- Naive Bayes assumes **all features Xi are conditionally independent given the class Vj**
```
P(X | Vj) = ∏i P(Xi | Vj)
```

### Parameter Estimation Problems

#### Full Joint Model:
- Model P(X₁, ..., Xₙ | Y)
- For k classes, n features, v values/feature:
  - Need k × (v^n-1) + k-1 independent parameters (exponential in n)

#### Naive Bayes Model:
- Model P(X₁ | Y), ..., P(Xₙ | Y) separately
- Need only k × n × (v-1) + (k-1) parameters (linear in n)

---

## Parameter Estimation: Full Joint vs. Naive Bayes

| Setup           | Needed Parameters                        | Growth Rate |
|-----------------|------------------------------------------|-------------|
| Full Joint      | k(v^n-1)+(k-1) | Exponential in n |
| Naive Bayes     | k·n·(v-1)+(k-1) | Linear in n |

Where: k = number of classes, v = values/feature, n = features

### Detailed Explanation Example (n=2, v=2, k=2):

**Dependent (Full Joint) Case:**
- Features: X₁, X₂ (both binary: 0 or 1)
- Classes: C₁, C₂
- Need to compute joint probabilities:

```
P(X₁=0, X₂=0 | C₁)    P(X₁=0, X₂=1 | C₁)
P(X₁=1, X₂=0 | C₁)    P(X₁=1, X₂=1 | C₁)
P(X₁=0, X₂=0 | C₂)    P(X₁=0, X₂=1 | C₂)
P(X₁=1, X₂=0 | C₂)    P(X₁=1, X₂=1 | C₂)
```

- Total probabilities: v^n × k = 2² × 2 = 8
- All must sum to 1 → independent parameters = 8 - 1 = 7
- Formula check: k(v^n-1) + (k-1) = 2(2²-1) + 1 = 2(3) + 1 = 7 ✓

**Independent (Naive Bayes) Case:**

Class Priors:
- P(C₁) = p (one free parameter)
- P(C₂) = 1-p (determined)

For class C₁:
- P(X₁=0|C₁) = a → P(X₁=1|C₁) = 1-a
- P(X₂=0|C₁) = b → P(X₂=1|C₁) = 1-b

For class C₂:
- P(X₁=0|C₂) = c → P(X₁=1|C₂) = 1-c
- P(X₂=0|C₂) = d → P(X₂=1|C₂) = 1-d

Independent parameters needed: p, a, b, c, d = **5 parameters**
Formula check: k·n(v-1) + (k-1) = 2·2(1) + 1 = 5 ✓

**Key Insight:** As attributes increase, exponential vs. linear difference becomes dramatic:
- 10 features: Full Joint = 2^10 = 1024, Naive Bayes = 20 parameters
- 20 features: Full Joint = 2^20 ≈ 1 million, Naive Bayes = 40 parameters

## Algorithm Steps and Example Calculations

### Core Steps of Naive Bayes Algorithm

**Training Phase:**
1. **Estimate P(Vj)** — prior probability from class frequencies
   ```
   P(Vj) = (Number of instances with class Vj) / (Total instances)
   ```

2. **Estimate P(Xi=ai | Vj)** — per-feature conditional probabilities per class
   ```
   P(Xi=ai | Vj) = (Count of instances where Xi=ai and class=Vj) / (Count of instances with class=Vj)
   ```

**Prediction Phase:**
3. For query instance with attribute values a₁, a₂, ..., aₙ:
   ```
   P(Vj | X) ∝ P(Vj) × ∏i P(Xi=ai | Vj)
   ```

4. Assign class with maximum posterior probability:
   ```
   V_MAP = argmax_Vj [P(Vj) × ∏i P(Xi=ai | Vj)]
   ```

## Practical Issues: Zero Frequency & Numerical Underflow

### 1. Zero Frequency Problem

**Problem:** If test instance has unseen attribute value for a class, conditional probability = 0, making entire product = 0

**Example:** 
- Training data: Never saw "Exports = Avg" with "Economy = Great"
- Test data: New instance has "Exports = Avg" and "Economy = Great"
- Result: P(Exports = Avg | Economy = Great) = 0 → entire classification fails

**Solution: Laplace (Add-m) Smoothing**

```
P(Xi=ai | Vj) = (Count + m·p) / (Total Count in Class + m)
```

Where:
- m = smoothing parameter (typically equals number of possible values for attribute)
- p = assumed prior probability (typically uniform: 1/k where k = number of possible values)

**Example Calculation:**
- Attribute "Exports" has 2 possible values
- Without smoothing: P(Exports=Avg|Economy=Great) = 0/3 = 0
- With m=2 smoothing and p=0.5: P(Exports=Avg|Economy=Great) = (0+2×0.5)/(3+2) = 1/5 = 0.2

### 2. Numerical Underflow Problem

**Problem:** Product of many small probabilities (< 1) underflows to zero
- Example: 100 features, each with probability 0.01
- Product = 0.01^100 ≈ 0 (too small for floating-point representation)

**Solution: Use Log-Space Arithmetic**

Instead of:
```
P(h|D) = P(h) × P(D₁|h) × P(D₂|h) × ... × P(D₁₀₀|h)
```

Use:
```
log[P(h|D)] = log[P(h)] + log[P(D₁|h)] + log[P(D₂|h)] + ... + log[P(D₁₀₀|h)]
```

**Advantage:** 
- Sums of logs avoid underflow
- Comparison result unchanged: log(a) > log(b) ⟺ a > b
- Numerically stable for computation

## Worked Examples with Step-by-Step Solutions

### Example 1: Economy Classification (Discrete Attributes)

**Dataset:**
| Economy | IT | Chemicals | Crops | Exports | Class |
|---------|-----|-----------|-------|---------|-------|
| Good | Good | Bad | Good | Good | Great |
| Good | Good | Bad | Bad | Bad | Great |
| Bad | Bad | Good | Good | Good | Great |
| Bad | Bad | Bad | Good | Bad | Not Great |
| Bad | Bad | Bad | Bad | Good | Not Great |

**Task:** Classify new instance: X_new = <IT=Good, Chemicals=Avg, Crops=Good, Exports=Avg>

**Step 1: Calculate Prior Probabilities**
```
Total instances = 5
Great instances = 3
Not Great instances = 2

P(Great) = 3/5 = 0.6
P(Not Great) = 2/5 = 0.4
```

**Step 2: Calculate Conditional Probabilities for Each Attribute**

For class "Great":
```
P(IT=Good | Great) = 2/3
P(Chemicals=Avg | Great) = 0/3 = 0 ← Zero frequency problem!
P(Crops=Good | Great) = 3/3 = 1
P(Exports=Avg | Great) = 0/3 = 0 ← Zero frequency problem!
```

For class "Not Great":
```
P(IT=Good | Not Great) = 0/2 = 0
P(Chemicals=Avg | Not Great) = 0/2 = 0
P(Crops=Good | Not Great) = 1/2 = 0.5
P(Exports=Avg | Not Great) = 0/2 = 0
```

**Step 3: Apply Laplace Smoothing**

For each attribute with value not appearing in class: add m=1 to numerator, m to denominator
(m = number of possible values for attribute)

**Assuming each attribute has 3 possible values (Good, Bad, Avg):**

For class "Great" (3 instances total):
```
P(IT=Good | Great) = (2+1)/(3+3) = 3/6 = 0.5
P(Chemicals=Avg | Great) = (0+1)/(3+3) = 1/6 = 0.167
P(Crops=Good | Great) = (3+1)/(3+3) = 4/6 = 0.667
P(Exports=Avg | Great) = (0+1)/(3+3) = 1/6 = 0.167
```

For class "Not Great" (2 instances total):
```
P(IT=Good | Not Great) = (0+1)/(2+3) = 1/5 = 0.2
P(Chemicals=Avg | Not Great) = (0+1)/(2+3) = 1/5 = 0.2
P(Crops=Good | Not Great) = (1+1)/(2+3) = 2/5 = 0.4
P(Exports=Avg | Not Great) = (0+1)/(2+3) = 1/5 = 0.2
```

**Step 4: Calculate Posterior Probabilities**

For class "Great":
```
P(Great | X) ∝ P(Great) × P(IT=Good|Great) × P(Chemicals=Avg|Great) × P(Crops=Good|Great) × P(Exports=Avg|Great)
           = 0.6 × 0.5 × 0.167 × 0.667 × 0.167
           = 0.6 × 0.5 × 0.167 × 0.667 × 0.167
           = 0.00333
```

For class "Not Great":
```
P(Not Great | X) ∝ P(Not Great) × P(IT=Good|Not Great) × P(Chemicals=Avg|Not Great) × P(Crops=Good|Not Great) × P(Exports=Avg|Not Great)
                = 0.4 × 0.2 × 0.2 × 0.4 × 0.2
                = 0.4 × 0.2 × 0.2 × 0.4 × 0.2
                = 0.00064
```

**Step 5: Classification Decision**

```
P(Great | X) = 0.00333 > P(Not Great | X) = 0.00064

Therefore, X_new is classified as: GREAT ✓
```

### Example 2: Play Tennis Classification

**Dataset (14 instances):**

| Day | Outlook | Temperature | Humidity | Wind | Play Tennis |
|-----|---------|------------|----------|------|-------------|
| 1 | Sunny | Hot | High | Weak | No |
| 2 | Sunny | Hot | High | Strong | No |
| 3 | Overcast | Hot | High | Weak | Yes |
| 4 | Rain | Mild | High | Weak | Yes |
| 5 | Rain | Cool | Normal | Weak | Yes |
| 6 | Rain | Cool | Normal | Strong | No |
| 7 | Overcast | Cool | Normal | Strong | Yes |
| 8 | Sunny | Mild | High | Weak | No |
| 9 | Sunny | Cool | Normal | Weak | Yes |
| 10 | Rain | Mild | Normal | Weak | Yes |
| 11 | Sunny | Mild | Normal | Strong | Yes |
| 12 | Overcast | Mild | High | Strong | Yes |
| 13 | Overcast | Hot | Normal | Weak | Yes |
| 14 | Rain | Mild | High | Strong | No |

**Task:** Classify X_new = <Outlook=Sunny, Temperature=Cool, Humidity=High, Wind=Strong>

**Step 1: Calculate Prior Probabilities**
```
Total instances = 14
Play=Yes instances = 9
Play=No instances = 5

P(Play=Yes) = 9/14 = 0.643
P(Play=No) = 5/14 = 0.357
```

**Step 2: Build Frequency Tables**

**Outlook frequencies:**
```
                Play=Yes  Play=No
Sunny             2         3
Overcast          4         0
Rain              3         2
```

**Temperature frequencies:**
```
                Play=Yes  Play=No
Hot               2         2
Mild              4         2
Cool              3         1
```

**Humidity frequencies:**
```
                Play=Yes  Play=No
High              3         4
Normal            6         1
```

**Wind frequencies:**
```
                Play=Yes  Play=No
Strong            3         3
Weak              6         2
```

**Step 3: Calculate Conditional Probabilities**

For class "Play=Yes" (9 instances):
```
P(Outlook=Sunny | Yes) = 2/9 = 0.222
P(Temperature=Cool | Yes) = 3/9 = 0.333
P(Humidity=High | Yes) = 3/9 = 0.333
P(Wind=Strong | Yes) = 3/9 = 0.333
```

For class "Play=No" (5 instances):
```
P(Outlook=Sunny | No) = 3/5 = 0.6
P(Temperature=Cool | No) = 1/5 = 0.2
P(Humidity=High | No) = 4/5 = 0.8
P(Wind=Strong | No) = 3/5 = 0.6
```

**Step 4: Calculate Posterior Probabilities**

For Play=Yes:
```
P(Yes | X) ∝ P(Yes) × P(Outlook=Sunny|Yes) × P(Temp=Cool|Yes) × P(Humidity=High|Yes) × P(Wind=Strong|Yes)
          = 0.643 × 0.222 × 0.333 × 0.333 × 0.333
          = 0.643 × 0.222 × 0.333 × 0.333 × 0.333
          = 0.00793
```

For Play=No:
```
P(No | X) ∝ P(No) × P(Outlook=Sunny|No) × P(Temp=Cool|No) × P(Humidity=High|No) × P(Wind=Strong|No)
         = 0.357 × 0.6 × 0.2 × 0.8 × 0.6
         = 0.357 × 0.6 × 0.2 × 0.8 × 0.6
         = 0.0257
```

**Step 5: Classification Decision**

```
P(No | X) = 0.0257 > P(Yes | X) = 0.00793

Therefore, X_new is classified as: NO (Don't play tennis) ✓
```

**Interpretation:** Despite sunny outlook, the combination of cool temperature, high humidity, and strong wind results in not playing tennis.

### Example 3: Text Classification - Sentiment Analysis

**Training Dataset:**
```
D1: "A great game" → Class: sports
D2: "election is over" → Class: not sports
D3: "very clean match" → Class: sports
D4: "a clean but forgettable game" → Class: sports
D5: "it was a close election" → Class: not sports
```

**Task:** Classify D_new = "A very close game"

**Step 1: Calculate Prior Probabilities**
```
Total documents = 5
Sports documents = 3
Not sports documents = 2

P(sports) = 3/5 = 0.6
P(not sports) = 2/5 = 0.4
```

**Step 2: Build Word Frequency Table**

First, identify all unique words (vocabulary):
{a, great, game, election, is, over, very, clean, match, but, forgettable, close, it, was}

Count word occurrences per class:
```
Word            Sports  Not Sports
a                 2         1
great             1         0
game              2         0
election          0         2
is                0         1
over              0         1
very              1         0
clean             2         0
match             1         0
but               1         0
forgettable       1         0
close             1         1
it                0         1
was               0         1
---
Total words:     12        8
Vocabulary size: 14
```

**Step 3: Calculate Word Probabilities (WITHOUT Smoothing)**

For class "sports" (12 total words):
```
P(a | sports) = 2/12 = 0.167
P(very | sports) = 1/12 = 0.083
P(close | sports) = 1/12 = 0.083
P(game | sports) = 2/12 = 0.167
```

For class "not sports" (8 total words):
```
P(a | not sports) = 1/8 = 0.125
P(very | not sports) = 0/8 = 0 ← Zero frequency problem!
P(close | not sports) = 1/8 = 0.125
P(game | not sports) = 0/8 = 0 ← Zero frequency problem!
```

**Step 4: Apply Laplace Smoothing**

Add 1 to numerator, add vocabulary_size to denominator:

For class "sports" (12 + 14 = 26 in denominator):
```
P(a | sports) = (2+1)/(12+14) = 3/26 = 0.115
P(very | sports) = (1+1)/(12+14) = 2/26 = 0.077
P(close | sports) = (1+1)/(12+14) = 2/26 = 0.077
P(game | sports) = (2+1)/(12+14) = 3/26 = 0.115
```

For class "not sports" (8 + 14 = 22 in denominator):
```
P(a | not sports) = (1+1)/(8+14) = 2/22 = 0.091
P(very | not sports) = (0+1)/(8+14) = 1/22 = 0.045
P(close | not sports) = (1+1)/(8+14) = 2/22 = 0.091
P(game | not sports) = (0+1)/(8+14) = 1/22 = 0.045
```

**Step 5: Calculate Posterior Probabilities**

Using log-space to avoid underflow:

For "sports":
```
log P(sports | D_new) = log P(sports) + log P(a|sports) + log P(very|sports) + log P(close|sports) + log P(game|sports)
                      = log(0.6) + log(0.115) + log(0.077) + log(0.077) + log(0.115)
                      = -0.511 + (-2.160) + (-2.567) + (-2.567) + (-2.160)
                      = -9.965
```

For "not sports":
```
log P(not sports | D_new) = log P(not sports) + log P(a|not sports) + log P(very|not sports) + log P(close|not sports) + log P(game|not sports)
                           = log(0.4) + log(0.091) + log(0.045) + log(0.091) + log(0.045)
                           = -0.916 + (-2.396) + (-3.101) + (-2.396) + (-3.101)
                           = -11.91
```

**Step 6: Classification Decision**

```
log P(sports | D_new) = -9.965 > log P(not sports | D_new) = -11.91

Therefore, D_new is classified as: SPORTS ✓
```

**Interpretation:** The presence of words like "very", "close", and "game" (more common in sports) results in sports classification.

## Text Classification with Naive Bayes

### Bag-of-Words Model
- Every document is a feature vector of word counts (order/position ignored)
- Probability of each word in a class estimated from training corpus

### Text Classification Challenges

**1. Zero Frequency (Unseen Words)**
- Words in test data but not in training vocabulary
- Solution: Laplace smoothing (add 1 to counts)

**2. Stop Words**
- Very frequent words (the, a, is) that add little discriminative value
- Can remove using predefined lists or top N frequent words
- **Note:** Often doesn't improve performance in practice

**3. Vocabulary Size**
- Includes all unique words from training data
- Affects smoothing denominator

---

## Advanced Techniques

### 1. Remove Stop Words
Common words (the, is, etc.) that add no discriminative value
```
Example: "A very close game" → "very close game"
```

### 2. Stemming
Group inflections (election, elected) as one word
```
Example: run, running, runs → run (root form)
```

### 3. N-grams
Use sequences of N words instead of individual words
```
Example: Instead of "clean" and "match", use "clean match" as one feature
Bigrams (2-grams): clean match, close election
Trigrams (3-grams): very close game
```

### 4. TF-IDF (Term Frequency - Inverse Document Frequency)
Scale word importance by how rare it is across documents
```
TF = (Number of times word appears in document) / (Total words in document)
IDF = log[(Total documents) / (Documents containing word)]
TF-IDF = TF × IDF
```
- Words appearing in many documents get lower weight
- Rare, specific words get higher weight

```
P(Spam | "offer") ∝ P("offer" | Spam) × P(Spam) = 0.60 × 0.20 = 0.12
```

## Key Takeaways

- **Naive Bayes is simple but powerful** - scales well with features due to conditional independence assumption
- **Training is fast** - only requires counting frequencies
- **Works surprisingly well** despite unrealistic independence assumption
- **Watch out for practical issues:**
  - Zero frequency → use Laplace smoothing
  - Numerical underflow → use log-space arithmetic
- **Heavily used in:**
  - Text classification and spam detection
  - Sentiment analysis
  - Email filtering
  - Document categorization
