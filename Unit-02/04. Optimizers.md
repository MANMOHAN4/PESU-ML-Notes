## 1. Optimization Overview

### What is Optimization in Deep Learning?

**Goal:** Find parameters (weights, biases) that minimize loss function.

**Challenge:** In most ML scenarios, we care about **performance measure P**, but we optimize **loss function J(θ)** instead, hoping improvement in J leads to improvement in P.

**Optimization algorithms:** Methods to efficiently search parameter space and find good weights.

---

## 2. Gradient Descent Recap

### Core Principles

**Update Rule:**
```
θ_{new} = θ_{old} - η × ∇θJ(θ_{old})

where:
  θ = parameters (weights, biases)
  η = learning rate (step size)
  ∇θJ = gradient of loss w.r.t. parameters
```

**Algorithm:**
```
1. Initialize weights randomly
2. While not converged:
     a. Compute gradients: ∇θJ
     b. Update parameters: θ ← θ - η∇θJ
3. Return learned θ
```

### Key Insight

**Direction:** Move in opposite direction to gradient (steepest descent)

**Step size:** Learning rate η controls how far to move

## 3. Batch Gradient Descent

### Definition

**Batch Gradient Descent:** Calculate error for each example in entire training dataset, update model **only once** after evaluating all examples.

### Algorithm

```
For epoch in 1 to num_epochs:
  For each training example (x, y):
    Compute prediction ŷ = forward_pass(x, θ)
    Compute error: e = ŷ - y
    Accumulate gradient: ∇θJ += e × ∂ŷ/∂θ
  
  Update once: θ ← θ - η × ∇θJ  [after all examples]
```

### Advantages

1. **Computational efficiency:** Fewer updates = fewer computations
2. **Stable convergence:** Stable error gradient, smooth convergence
3. **Parallelizable:** Can compute errors in parallel across training data
4. **Memory efficient:** Can accumulate errors across entire dataset

### Disadvantages

1. **Premature convergence:** Stable gradient may converge to local minimum
2. **Memory requirements:** Need entire training dataset in memory
3. **Slow updates:** Model updates only once per epoch
4. **Slow training:** For large datasets, training becomes very slow
5. **May miss better solutions:** Single update per epoch limits exploration

### When to Use

- Small training datasets
- When stability is critical
- When computational resources allow loading entire dataset

## 4. Stochastic Gradient Descent (SGD)

### Definition

**Stochastic Gradient Descent:** Calculate error and **update model immediately** for each training example.

### Algorithm

```
For epoch in 1 to num_epochs:
  For each training example (x, y):
    Compute prediction ŷ = forward_pass(x, θ)
    Compute gradient: ∇θJ = (ŷ - y) × ∂ŷ/∂θ
    Update: θ ← θ - η × ∇θJ  [immediate update!]
```

### Advantages

1. **Frequent insights:** Get performance feedback frequently
2. **Simple to implement:** Easiest to understand and code
3. **Faster learning:** More frequent updates can learn faster
4. **Avoid local minima:** Noisy updates can escape local minima
5. **Memory efficient:** Process one example at a time

### Disadvantages

1. **Computationally expensive:** Many updates slow down training
2. **Noisy gradients:** High variance in gradient estimates
3. **Unstable convergence:** Parameters and error jump around
4. **Hard to settle:** Difficult to converge at minimum (oscillates around)
5. **Takes longer:** May never fully converge despite many updates

### Visualization

```
Batch GD:           Smooth path to minimum
        ∖
         ∖
          ∖ 
           ∖ → minimum

SGD:                Noisy, oscillating path
↙↗↙↗↙↗↙↗...
→ minimum (noisy!)
```

### When to Use

- Large training datasets where batch is too expensive
- When escaping local minima is important
- Simple baseline for comparison

## 5. Mini-Batch Gradient Descent

### Definition

**Mini-Batch GD:** Split training dataset into small batches, update model after computing error for **entire batch**.

### Algorithm

```
For epoch in 1 to num_epochs:
  Shuffle training data
  
  For each batch B of size m:
    For each example (x,y) in B:
      Compute error and accumulate gradient
    
    Update once per batch: θ ← θ - η × ∇θJ_batch
```

### Advantages

1. **Balanced approach:** Combines benefits of both batch and SGD
2. **More frequent updates:** Updates after each batch (> 1 per epoch)
3. **Computational efficiency:** Batched operations are efficient
4. **Hardware optimized:** GPU/TPU parallelization for batches
5. **Robust convergence:** Balance between stability and exploration
6. **Industry standard:** Most common in deep learning

### Disadvantages

1. **Requires tuning:** Must choose batch size (another hyperparameter)
2. **Memory:** Need to store entire batch in memory
3. **Error accumulation:** Must accumulate errors across batch examples

### Choosing Batch Size

**Guidelines:**
- **Small training set (< 2000 examples):** Use batch GD (m = entire set)
- **Typical range:** m ∈ {32, 64, 128, 256}
- **Powers of 2:** Often tuned to hardware (2^5, 2^6, 2^7, etc.)
- **GPU memory:** Should fit entire batch in GPU VRAM
- **Larger batch:** More stable gradients, faster computation
- **Smaller batch:** More frequent updates, better generalization

**Experimental approach:**
```
Try: [16, 32, 64, 128, 256, 512]
Evaluate on validation set
Choose batch size with best performance
```

## 6. Exponentially Weighted Averages (EWA)

### Motivation

**Problem:** In time series or optimization, raw measurements are noisy. We want smooth trends.

**Example:** Temperature across days
```
Day 1: 30°C
Day 2: 28°C  
Day 3: 33°C  ← spike
Day 4: 29°C
Day 5: 31°C

How to estimate trend? Average is noisy!
```

### Formula

**Exponentially Weighted Moving Average:**
```
V_t = β × V_{t-1} + (1-β) × θ_t

where:
  V_t = smoothed estimate at time t
  V_{t-1} = previous smoothed estimate
  θ_t = current measurement
  β = decay factor (0 < β < 1)
```

### Interpretation

**Parameter β determines:**
- β (β ≈ previous): More weight on history (trend)
- (1-β) (1-β ≈ current): More weight on current value (responsiveness)

**Effective window:**
```
Approximately averages over last 1/(1-β) measurements

β = 0.9  → averages last 10 measurements
β = 0.99 → averages last 100 measurements
β = 0.5  → averages last 2 measurements
```

### Effect of β

**β = 0.9 (smooth curve):**
```
V_t
  |    ____----
  |  _-
  |_/_________________ t
```
- Smooth, adapts slowly to changes
- Emphasizes trends
- Useful for gradual trends

**β = 0.1 (noisy curve):**
```
V_t
  |  ↙↗↙↗↙↗↙↗
  |_/_________________ t
```
- Follows current values closely
- Responds quickly to changes
- Can overshoot on noise

### Example Calculation

```
Temperature smoothing with β = 0.9:

Day 1: θ₁ = 30°C
       V₁ = 30°C (initialize)

Day 2: θ₂ = 28°C
       V₂ = 0.9 × 30 + 0.1 × 28 = 27 + 2.8 = 29.8°C

Day 3: θ₃ = 33°C
       V₃ = 0.9 × 29.8 + 0.1 × 33 = 26.82 + 3.3 = 30.12°C

Day 4: θ₄ = 29°C
       V₄ = 0.9 × 30.12 + 0.1 × 29 = 27.108 + 2.9 = 30.008°C

Result: Smooth curve [30, 29.8, 30.12, 30.008, ...]
```

## 7. Gradient Descent with Momentum

### Problem Momentum Solves

**Standard gradient descent can oscillate:**
```
Loss
  |     /\___/\___
  |    / (oscillates!)
  |___/__________ iterations

Reason: Gradient direction changes with curvature
```

### Solution: Momentum

**Idea:** Add "momentum" from previous gradient directions. Helps smooth oscillations while maintaining progress.

### Momentum Algorithm

```
Initialize:
  V_dW = 0
  V_db = 0

For iteration t:
  1. Compute gradients: dW_t, db_t
  
  2. Update velocity (accumulated gradient):
     V_dW = β × V_dW + (1-β) × dW_t
     V_db = β × V_db + (1-β) × db_t
  
  3. Update parameters using velocity:
     W ← W - η × V_dW
     b ← b - η × V_db

where β ≈ 0.9 (typical)
```

### Interpretation

**Velocity:** Accumulates gradient direction over time

**Effect:**
1. **Damps oscillations:** Previous velocity smooths current gradient
2. **Accelerates:** Consistent gradients accumulate
3. **Escapes saddle points:** Momentum carries through flat regions
4. **Reduces local minima**: Can escape with accumulated velocity

### Advantages

1. **Smoother convergence:** Oscillations are dampened
2. **Faster convergence:** Accumulated momentum speeds up
3. **Flat regions:** Can cross flat regions where gradient ≈ 0
4. **Escapes local minima:** Momentum can carry over local barriers

### Disadvantages

1. **Can overshoot:** Momentum can carry past minimum
2. **Hyperparameter tuning:** Must choose β (typically 0.9)
3. **May oscillate:** With very fast changes, can create oscillations

## 8. RMSprop (Root Mean Square Propagation)

### Problem RMSprop Solves

**Issue:** Different parameters may have very different gradient magnitudes.

**Example:**
```
Parameter 1: Very steep (large gradient)
Parameter 2: Very flat (small gradient)

Standard gradient descent:
  w₁ ← w₁ - η × large_gradient   (big step)
  w₂ ← w₂ - η × small_gradient   (tiny step)

Result: Oscillates in steep direction, barely moves in flat!
```

### RMSprop Algorithm

```
Initialize:
  S_dW = 0
  S_db = 0
  ε = 1e-8 (small constant to prevent division by zero)

For iteration t:
  1. Compute gradients: dW_t, db_t
  
  2. Accumulate squared gradients (exponential average):
     S_dW = β₂ × S_dW + (1-β₂) × (dW_t)²
     S_db = β₂ × S_db + (1-β₂) × (db_t)²
  
  3. Update parameters with adaptive learning rate:
     W ← W - η × dW_t / (√S_dW + ε)
     b ← b - η × db_t / (√S_db + ε)

where β₂ ≈ 0.999
```

### Adaptive Learning Rate

**Key insight:**
- If S_dW is small → divide by small number → large update
- If S_dW is large → divide by large number → small update

**Effect:**
```
Steep direction:
  Large gradients → Large S_dW → Small update (slow down) ✓

Flat direction:
  Small gradients → Small S_dW → Large update (speed up) ✓

Result: Balanced learning across all dimensions!
```

### Advantages

1. **Adaptive learning rates:** Different per parameter
2. **Fast convergence:** Speeds up flat directions
3. **Oscillation reduction:** Dampens steep directions
4. **Robust:** Works well across different problems

### Disadvantages

1. **Memory:** Need to store S_dW, S_db
2. **Hyperparameter:** Must tune β₂
3. **Still may need momentum:** Some problems benefit from momentum + RMSprop

## 9. Adam Optimizer

### Definition

**Adam (Adaptive Moment Estimation):** Combines momentum and RMSprop.

**Best of both worlds:**
```
Momentum: Accumulates gradient direction
RMSprop: Adapts learning rate per parameter
Adam: Uses both!
```

### Adam Algorithm

```
Initialize:
  V_dW = 0, V_db = 0  (momentum terms)
  S_dW = 0, S_db = 0  (RMSprop terms)

For iteration t:
  1. Compute gradients: dW_t, db_t
  
  2. Momentum update:
     V_dW = β₁ × V_dW + (1-β₁) × dW_t
     V_db = β₁ × V_db + (1-β₁) × db_t
  
  3. RMSprop update:
     S_dW = β₂ × S_dW + (1-β₂) × (dW_t)²
     S_db = β₂ × S_db + (1-β₂) × (db_t)²
  
  4. Bias correction (important for early iterations!):
     V_dW_corrected = V_dW / (1 - β₁^t)
     S_dW_corrected = S_dW / (1 - β₂^t)
     (similar for b terms)
  
  5. Parameter update:
     W ← W - η × V_dW_corrected / (√S_dW_corrected + ε)
     b ← b - η × V_db_corrected / (√S_db_corrected + ε)
```

### Typical Hyperparameters

```
Default values (usually work well):
  α (learning rate): 0.001  [try: 0.0001, 0.001, 0.01]
  β₁ (momentum): 0.9
  β₂ (RMSprop): 0.999
  ε: 1e-8
```

### Advantages

1. **Adaptive learning rates:** Per-parameter adaptation
2. **Momentum:** Accelerates training
3. **Robust:** Works across many architectures
4. **Well-tuned defaults:** Default hyperparameters work surprisingly well
5. **Widely used:** Industry standard for deep learning
6. **Fast convergence:** Often converges in fewer epochs

### Disadvantages

1. **Memory intensive:** Stores V and S for all parameters
2. **Hyperparameter sensitive:** Still has learnable hyperparameters
3. **May converge to wrong solutions:** Not guaranteed global optimum
4. **Requires tuning:** May not work with default parameters for all problems

### When to Use Adam

**Adam should be your default choice unless:**
- You have a well-tuned SGD + momentum
- Your problem specifically benefits from different optimizer
- Memory is severely constrained

## 10. Learning Rate Decay

### Problem

**With constant learning rate:**
```
Early training: Large steps, fast learning
Late training: Same step size, oscillates around minimum
```

**Better:** Start with large learning rate, gradually decrease.

### Learning Rate Decay Strategies

**1. Linear Decay:**
```
α_t = α₀ × (1 - t/T)

where t = current iteration, T = total iterations
```

**2. Exponential Decay:**
```
α_t = α₀ × e^(-decay_rate × t)
```

**3. Step-based Decay:**
```
If iteration % step_interval == 0:
  α ← α × decay_factor

Example: Every 10 epochs, multiply α by 0.1
```

**4. Manual Decay:**
```
Monitor validation accuracy
If progress stalls: decrease α manually
```

### Example Decay Schedule

```
Initial α = 0.1

Epoch   Learning Rate
1       0.1
2       0.1
3       0.1
...
10      0.05    (step decay: × 0.5)
...
20      0.025   (step decay: × 0.5)
...
30      0.0125  (step decay: × 0.5)
```

### Advantages

1. **Faster early training:** Large steps when far from optimum
2. **Better convergence:** Small steps near optimum
3. **Smoother curves:** Fine-tuning near minimum
4. **Better final accuracy:** Reaches better minimum

## 11. Comparison and Selection

### Algorithm Comparison

| Algorithm | Update Freq | Compute | Memory | Convergence | Tuning |
|-----------|------------|---------|--------|-------------|--------|
| **Batch GD** | Once/epoch | Fast | Low | Smooth | Easy |
| **SGD** | Per sample | Slow | Low | Noisy | Easy |
| **Mini-batch** | Per batch | Fast | Medium | Good | Medium |
| **Momentum** | Per batch | Fast | Medium | Fast | Medium |
| **RMSprop** | Per batch | Fast | Medium | Fast | Medium |
| **Adam** | Per batch | Fast | High | Very fast | Medium |

### Decision Tree

```
Start with problem
  ├─ Small dataset (< 10k)?
  │   └─ Use: Batch GD or SGD
  │
  ├─ Large dataset?
  │   ├─ Simple problem?
  │   │   └─ Use: Mini-batch + SGD/Momentum
  │   │
  │   └─ Complex problem (Deep NN)?
  │       └─ Use: Adam (default)
  │           ├─ If diverges: Lower learning rate
  │           ├─ If too slow: Increase learning rate
  │           └─ If stuck: Try SGD + Momentum + manual tuning
  │
  └─ Special cases?
      ├─ Production: Use Adam (proven, stable)
      ├─ Research: Try multiple optimizers
      └─ Mobile: Use SGD (smallest memory)
```

### Practical Recommendations

**Best for beginners:**
```
Use: Mini-batch (32-128) + Adam
Learning rate: 0.001
Adjust if needed based on performance
```

**Best for production:**
```
Use: Adam or SGD + Momentum
Learning rate decay: Step-based or exponential
Ensemble multiple trained models
```

**Best for complex problems:**
```
Use: Adam with learning rate decay
Batch size: 32-256 (depends on GPU)
Monitor validation loss for early stopping
```
