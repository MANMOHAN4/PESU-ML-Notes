## Unsupervised Learning Fundamentals

### Supervised vs Unsupervised Learning

**Supervised Learning:**
- Uses labeled data (data + label)
- Algorithm is taught with labels
- Goal: Learn mapping from features to target variable
- Examples: Classification, Regression

**Unsupervised Learning:**
- Works with unlabeled data (data only, no label)
- No explicit target variable
- Goal: Find hidden structure in data
- Algorithm must discover patterns on its own

### Why Unsupervised Learning?

**Scenarios where unsupervised learning is needed:**
- Labeled data is expensive or unavailable
- Want to explore data structure
- Feature engineering before supervised learning
- Anomaly detection
- Customer segmentation

## Clustering Overview

### Definition

**Clustering** is the process of dividing a dataset into groups (clusters) where:
- **Intra-cluster distances:** Minimized (similar objects close together)
- **Inter-cluster distances:** Maximized (different objects far apart)

### Clustering Goal

**Find groups of objects such that:**
- Objects in same group are similar to each other
- Objects in different groups are different from each other
- Based on shared unknown characteristics

### Applications of Clustering

- **Marketing:** Customer segmentation
- **Insurance:** Risk assessment and grouping
- **City Planning:** Geographic clustering
- **Earthquake Studies:** Epicenter clustering
- **Biology:** Gene expression clustering
- **Computer Vision:** Image segmentation

## Hierarchical Clustering Definition

### What is Hierarchical Clustering?

**Hierarchical Clustering** is an unsupervised technique that:
- Creates clusters in a predefined order
- Forms tree-like hierarchical structure (dendrogram)
- Orders clusters from top to bottom (or bottom to top)
- Similar clusters grouped together and arranged hierarchically

### Analogy

Think of organizing files in folders and subfolders:
```
Computer
├── Documents
│   ├── Work
│   │   ├── Project1
│   │   └── Project2
│   └── Personal
│       ├── Finance
│       └── Health
├── Pictures
│   ├── Vacation
│   └── Family
└── Videos
```

### Key Advantages

✅ **No pre-specified K:** Don't need to specify number of clusters beforehand  
✅ **Flexible stopping:** Can cut dendrogram at any level to get desired K clusters  
✅ **Hierarchical information:** Shows relationships between clusters  
✅ **Interpretable:** Visual representation easy to understand

## Agglomerative Hierarchical Clustering

### Definition

**Agglomerative** = Bottom-Up approach

**Process:**
1. Start with each data point as its own cluster (n clusters initially)
2. Find the two closest clusters and merge them
3. Update proximity matrix
4. Repeat until all points in one cluster

### Intuition: Party Analogy

```
Initially: Strangers arriving at party (n separate clusters)
Step 1-2: Most similar people start talking (merge closest clusters)
Step 3-4: Friend groups form (clusters grow)
Final: Everyone in one big friend circle (single cluster)
```

### Algorithm Steps

**Step 1:** Compute proximity (distance/similarity) matrix
- Calculate distance between every pair of data points
- Creates n×n distance matrix

**Step 2:** Let each data point be a cluster
- n clusters initially, each with one point

**Step 3:** Repeat until convergence:
- Find two closest clusters
- Merge them into one cluster
- Update proximity matrix

**Step 4:** Termination
- Stop when single cluster remains (or other stopping criterion)

### Agglomerative Algorithm Pseudocode

```
procedure AGGLOMERATIVE(data points, linkage method):
    clusters ← each point as individual cluster
    proximity_matrix ← compute distances between all points
    
    while number of clusters > 1:
        find pair of closest clusters (i, j)
        merge clusters i and j into new cluster
        update proximity_matrix:
            remove rows/cols for i and j
            add row/col for merged cluster using linkage method
    
    return hierarchy (dendrogram)
```

### Key Challenge: Distance Between Clusters

**Question:** When clusters have multiple points, how to measure distance?

**Example:**
- Cluster 1: {A, B} with 2 points
- Cluster 2: {C, D, E} with 3 points

Which distances to use?
- A-C, A-D, A-E, B-C, B-D, B-E?

**Answer:** Use different linkage methods!

## Divisive Hierarchical Clustering

### Definition

**Divisive** = Top-Down approach

**Process:**
1. Start with all data points in one cluster
2. Split the cluster into smaller clusters
3. Continue splitting until each point is own cluster

### Algorithm Steps

**Step 1:** Start with single cluster containing all data points

**Step 2:** Partition data into smaller groups using termination criterion

**Stopping Criterion Examples:**
- Minimum sum of squared errors threshold
- Desired number of clusters reached
- Dissimilarity exceeds threshold

**Step 3:** Repeat splitting until termination condition met

### Key Characteristic: Irreversibility

**Critical Property:**
- Once a cluster is split, split cannot be reversed/undone
- Exhibits high inflexibility
- Makes suboptimal early decisions difficult to correct

### Divisive Clustering Pseudocode

```
procedure DIVISIVE(data points):
    clusters ← [all data points as single cluster]
    
    while stopping criterion not met:
        select cluster C to split
        partition C into two sub-clusters using criterion
        replace C with two new clusters
    
    return hierarchy (dendrogram)
```

### Divisive vs Agglomerative

| Aspect | Agglomerative | Divisive |
|--------|---------------|---------| 
| **Direction** | Bottom-up | Top-down |
| **Start** | n clusters (points) | 1 cluster (all data) |
| **End** | 1 cluster | n clusters (points) |
| **Process** | Merge clusters | Split clusters |
| **Flexibility** | More flexible | Less flexible (irreversible) |
| **Popularity** | More commonly used | Less commonly used |
| **Complexity** | O(n² log n) typical | Often higher |

## Dendrogram

### What is a Dendrogram?

**Dendrogram** = Tree-like diagram showing hierarchical clustering

### Structure

```
Height (Dissimilarity)
│
├── 0.20 ─┐
│         ├─┐
│         │ ├─┐
├── 0.15 ─┤ │ ├─┐
│         │ │ │ │
├── 0.10 ─┤ │ │ ├─────┐
│         │ │ │ │     │
│         │ │ └─┴─┐   │
│         │ │     │   │
├── 0.05 ─┤ └─────┴─┐ │
│         │         │ │
│         └─────────┴─┴──
    Data Points (leaves)
```

### Reading a Dendrogram

**Vertical Axis (Height):** Distance/dissimilarity at which clusters merge
**Horizontal Axis:** Data points or clusters
**Horizontal Lines:** Represent merging of clusters
**Height of Line:** Shows distance where merge occurred

### Using Dendrogram for Clustering

**Cut the tree at different heights to get different numbers of clusters:**

```
If cut at height 0.2: Get 4 clusters
If cut at height 0.15: Get 3 clusters
If cut at height 0.10: Get 2 clusters
If cut at height 0.05: Get 1 cluster
```

### Advantages of Dendrogram

✅ Visual representation of hierarchy  
✅ Choose K by cutting at appropriate height  
✅ No need to pre-specify number of clusters  
✅ Shows relationships between clusters  
✅ Easy to interpret results

## Inter-Cluster Similarity Methods

### Problem: Distance Between Multi-Point Clusters

When clusters contain multiple points, different methods give different distances:

### Method 1: Single Linkage (MIN)

**Definition:** Distance between clusters = minimum distance between any two points

```
dist(Ci, Cj) = min{d(p, q) : p ∈ Ci, q ∈ Cj}
```

**Characteristics:**
- Uses closest pair of points
- Tends to form long chains (chaining effect)
- May create elongated clusters

**Example:**
```
C1 = {A, B}, C2 = {C, D, E}
dist(C1, C2) = min{d(A,C), d(A,D), d(A,E), d(B,C), d(B,D), d(B,E)}
```

### Method 2: Complete Linkage (MAX)

**Definition:** Distance between clusters = maximum distance between any two points

```
dist(Ci, Cj) = max{d(p, q) : p ∈ Ci, q ∈ Cj}
```

**Characteristics:**
- Uses farthest pair of points
- Tends to create compact, spherical clusters
- Conservative approach

**Example:**
```
C1 = {A, B}, C2 = {C, D, E}
dist(C1, C2) = max{d(A,C), d(A,D), d(A,E), d(B,C), d(B,D), d(B,E)}
```

### Method 3: Group Average

**Definition:** Distance between clusters = average distance between all pairs

```
dist(Ci, Cj) = (1 / |Ci| × |Cj|) × Σ_{p ∈ Ci, q ∈ Cj} d(p, q)
```

**Characteristics:**
- Balanced approach between single and complete
- More robust than single or complete linkage
- Commonly used in practice

### Method 4: Distance Between Centroids

**Definition:** Distance between clusters = distance between cluster centers

```
dist(Ci, Cj) = d(centroid(Ci), centroid(Cj))
```

Where centroid = mean of all points in cluster

**Characteristics:**
- Fast to compute
- Simple and intuitive
- Often used in practice

### Method 5: Ward's Method

**Definition:** Minimize increase in sum of squared errors (SSE)

```
dist(Ci, Cj) = Δ SSE = SSE(Ci ∪ Cj) - SSE(Ci) - SSE(Cj)
```

**Characteristics:**
- Criterion-based approach
- Minimizes within-cluster variance
- Produces balanced clusters
- Popular and effective

### Comparison Example

**Given:**
- C1 = {A, B} with points: A=(1,1), B=(2,3)
- C2 = {C, D, E} with points: C=(4,2), D=(5,3), E=(6,4)

**Distances:**
```
d(A,C)=3.16, d(A,D)=4.47, d(A,E)=5.74
d(B,C)=2.24, d(B,D)=3.16, d(B,E)=4.47

Single Linkage: min = 2.24
Complete Linkage: max = 5.74
Group Average: (3.16+4.47+5.74+2.24+3.16+4.47)/6 = 3.87
Centroid: distance((1.5,2), (5,3)) = 3.61
```

## Worked Example with Step-by-Step Solution

### Problem Setup

**Data Points:**
```
A = (2, 10)
B = (2, 5)
C = (8, 4)
D = (5, 8)
E = (7, 5)
F = (6, 4)
```

**Task:** Perform agglomerative hierarchical clustering

### Step 1: Calculate Distance Matrix

Using Euclidean distance:

```
        A      B      C      D      E      F
A     0.00   5.00  10.20   3.61   7.81   6.32
B     5.00   0.00   6.32   5.10   5.10   4.12
C    10.20   6.32   0.00   5.39   1.00   2.00
D     3.61   5.10   5.39   0.00   4.47   3.16
E     7.81   5.10   1.00   4.47   0.00   1.00
F     6.32   4.12   2.00   3.16   1.00   0.00
```

### Step 2: Find Closest Pair (Iteration 1)

**Minimum distance:** E-F = 1.00

**Action:** Merge E and F into cluster (EF)

### Step 3: Update Distance Matrix

Remove E and F, add (EF):

```
Using complete linkage:
d(A, EF) = max{d(A,E)=7.81, d(A,F)=6.32} = 7.81
d(B, EF) = max{d(B,E)=5.10, d(B,F)=4.12} = 5.10
d(C, EF) = max{d(C,E)=1.00, d(C,F)=2.00} = 2.00
d(D, EF) = max{d(D,E)=4.47, d(D,F)=3.16} = 4.47

New matrix:
        A      B      C      D     EF
A     0.00   5.00  10.20   3.61  7.81
B     5.00   0.00   6.32   5.10  5.10
C    10.20   6.32   0.00   5.39  2.00
D     3.61   5.10   5.39   0.00  4.47
EF    7.81   5.10   2.00   4.47  0.00
```

### Step 4: Find Next Closest Pair (Iteration 2)

**Minimum distance:** C-EF = 2.00

**Action:** Merge C and (EF) into cluster (CEF)

### Step 5-8: Continue Iterations

Continue process until all clusters merged:

**Iteration 3:** Merge C with minimal distance cluster
**Iteration 4:** Build larger clusters
**Iteration 5:** Continue until 1 cluster remains

### Final Dendrogram Structure

```
Height
  │
5 │                    ┌─────────────────────┐
  │                    │                     │
4 │          ┌─────────┤                     │
  │          │         │                     │
3 │    ┌─────┤    ┌────┤                     │
  │    │     │    │    │                     │
2 │    │  ┌──┴────┼─┐  │                     │
  │    │  │       │ │  │                     │
1 │    │  │   ┌───┘ │  │                     │
  │    │  │   │     │  │                     │
0 └────┴──┴───┴─────┴──┴─────────────────────
   A   D   B  C  (E-F) 
```

## Hierarchical vs Non-Hierarchical Clustering

### Comparison Table

| Aspect | Hierarchical | Non-Hierarchical |
|--------|--------------|------------------|
| **Structure** | Tree-like hierarchy | Flat partition |
| **Number of Clusters** | Choose by cutting dendrogram | Must specify K beforehand |
| **Reliability** | Less reliable, slower | More reliable, faster |
| **Error Sensitivity** | Problematic with high error | Works better with noise |
| **Interpretability** | Easy to read and understand | Harder to understand |
| **Reversibility** | Hard to undo merges (agglom.) | N/A |
| **Scalability** | Poor for large datasets | Better for large datasets |
| **Computational** | O(n² log n) typical | O(nKd) for K-Means |

### When to Use Each

**Use Hierarchical When:**
- Want to explore cluster structure
- Number of clusters unknown
- Need interpretable hierarchy
- Dataset is small to medium
- Visual representation important

**Use Non-Hierarchical When:**
- K (number of clusters) known
- Large dataset
- Need fast computation
- High-dimensional data
- Real-time clustering needed

## Strengths and Limitations

### Strengths of Hierarchical Clustering

✅ **No K specification:** Don't need to know number of clusters beforehand  
✅ **Visual interpretation:** Dendrogram easy to understand  
✅ **Flexibility:** Can cut at any level to get different K  
✅ **Hierarchical insight:** Shows relationships between clusters  
✅ **No iteration needed:** Deterministic algorithm (for agglomerative)  
✅ **Different dendrograms:** Can try different linkage methods  

### Limitations of Hierarchical Clustering

❌ **Computational cost:** O(n² log n) or worse - slow for large datasets  
❌ **Memory intensive:** Needs to store distance matrix  
❌ **Irreversibility (agglomerative):** Cannot undo merge decisions  
❌ **Sensitivity to linkage:** Different methods produce different results  
❌ **Noise sensitivity:** Outliers affect distances  
❌ **Difficulty with different sizes:** Hard to split clusters of different sizes  
❌ **Chain effect (single linkage):** Tends to create long elongated clusters  
❌ **Scalability:** Not suitable for very large datasets  

### Common Issues

**1. Chaining Effect (Single Linkage)**
- Clusters merge due to single bridges
- Creates elongated, unrealistic clusters

**2. Noise and Outliers**
- Significantly affect distance calculations
- Particularly problematic with single linkage
- May distort final clustering

**3. Different Cluster Sizes**
- Difficulty merging clusters of different sizes
- May force smaller clusters to merge with larger ones inappropriately

**4. Non-convex Clusters**
- Works better with convex clusters
- Struggles with non-convex or arbitrary shapes

## Key Takeaways

- **Hierarchical Clustering:** Creates tree-like clustering structure without pre-specifying K
- **Agglomerative:** Bottom-up approach, starts with individual points
- **Divisive:** Top-down approach, starts with all points in one cluster
- **Dendrogram:** Visual representation showing hierarchy and merge distances
- **Linkage Methods:** Different ways to measure distance between clusters (single, complete, average, centroid, Ward's)
- **Advantages:** Interpretability, flexibility, no K specification needed
- **Disadvantages:** Slow, memory-intensive, sensitive to linkage method choice
- **Applications:** Small-medium datasets, exploratory analysis, hierarchical structure understanding
