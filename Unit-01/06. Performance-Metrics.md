## 1. Performance Metrics Overview

### Why Performance Metrics?

After implementing a model, we get outputs (class predictions or probabilities). We need to measure **effectiveness** using metrics that compare model predictions against actual labels.

### Main Classification Metrics

- **Accuracy** - Overall correctness
- **Precision** - Correct predictions among positive predictions
- **Recall** - Correct positive predictions among actual positives
- **Specificity** - Correct negative predictions among actual negatives
- **F1 Score** - Harmonic mean of precision and recall
- **ROC/AUC** - Threshold-independent performance evaluation

## 2. Confusion Matrix Fundamentals

### Definition

The **Confusion Matrix** (contingency table) visualizes classifier performance by showing:

- What was predicted
- What was actually true
- In a 2×2 grid format

### Four Possible Outcomes for Binary Classification

Given an instance and classifier prediction:

| Term                    | Definition                                  | Symbol                  |
| ----------------------- | ------------------------------------------- | ----------------------- |
| **True Positive (TP)**  | Instance is positive AND predicted positive | ✓ Correct               |
| **False Negative (FN)** | Instance is positive BUT predicted negative | ✗ Wrong (Type II Error) |
| **True Negative (TN)**  | Instance is negative AND predicted negative | ✓ Correct               |
| **False Positive (FP)** | Instance is negative BUT predicted positive | ✗ Wrong (Type I Error)  |

### Confusion Matrix Layout

```
                  PREDICTED LABEL
                  Positive    Negative
ACTUAL LABEL  +   TP          FN
              -   FP          TN
```

### Understanding the Terminology

**Positive/Negative:**

- Refers to what the **model predicted**
- Not related to correctness

**True/False:**

- Indicates whether prediction is **correct or wrong**
- True = prediction matches reality
- False = prediction doesn't match reality

### Worked Example

**Scenario:** Medical diagnosis (disease detection)

**Data Summary:**

- Total 200 objects
- 100 have the disease (positive class)
- 100 don't have disease (negative class)

**Model Predictions:**

- 60 patients with disease correctly identified as sick
- 30 patients without disease correctly identified as healthy
- Remaining predictions are wrong

**Building Confusion Matrix:**

```
                   PREDICTED
                   Sick    Healthy
ACTUAL  Sick       60      40      (100 total)
        Healthy    30      70      (100 total)
                  (90)    (110)
```

**Calculations:**

- True Positives (TP) = 60 (correctly diagnosed sick)
- False Negatives (FN) = 40 (missed diagnosis - actually sick but predicted healthy)
- False Positives (FP) = 30 (false alarms - healthy but predicted sick)
- True Negatives (TN) = 70 (correctly diagnosed healthy)
- **Total Correct** = TP + TN = 60 + 70 = **90**
- **Total Wrong** = FP + FN = 30 + 40 = **70**

## 3. Binary Classification Metrics

### 1. Accuracy

**Definition:** Of all predictions made, how many were correct?

**Formula:**

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
         = Correct Predictions / Total Predictions
```

**Range:** 0 to 1 (or 0% to 100%)

**Interpretation:**

- 0.91 = Model correct 91% of the time
- Good when classes are balanced
- **Misleading for imbalanced datasets!**

**Example Problem:**

- Medical test data: 990 healthy, 10 diseased
- Naive model: "Everyone is healthy"
- Result: 990 correct, 10 wrong
- Accuracy = 990/1000 = **99%** ❌ Looks great but useless!
- **Never catches disease** (high false negative rate)

**When to Use:**

- ✓ Balanced dataset
- ✓ All errors equally costly
- ✗ Imbalanced data
- ✗ Different error costs

### 2. Precision

**Definition:** Of the positive predictions we made, how many were actually correct?

**Formula:**

```
Precision = TP / (TP + FP)
```

**Asks:** "When we predict positive, how reliable is that prediction?"

**Range:** 0 to 1

**Interpretation:**

- 0.91 = 91% of predicted positives are actually positive
- Measures **false positive rate**
- Higher precision = fewer false alarms

**Real-World Examples:**

**Spam Email Filter:**

- False positive (flagging real email as spam) is COSTLY
- User loses important emails
- Solution: High precision (only flag clearly spam)
- Trade-off: Some spam may slip through

**Product Recommendation:**

- False positive (recommending irrelevant products) is COSTLY
- User disengagement and frustration
- Solution: High precision (only recommend items they'll like)
- Trade-off: Miss some relevant recommendations

**When to Use:**

- ✓ Cost of false positive is high
- ✓ When you want to be conservative
- ✓ Limited resources to follow up
- ✗ When false negatives are worse

### 3. Recall (Sensitivity / True Positive Rate)

**Definition:** Of the actual positive instances, how many did we correctly identify?

**Formula:**

```
Recall = TP / (TP + FN)
```

**Asks:** "Did we catch all the positive cases?"

**Range:** 0 to 1

**Interpretation:**

- 0.95 = We caught 95% of actual positives
- Measures **false negative rate**
- Higher recall = miss fewer positives

**Real-World Examples:**

**Medical Diagnosis (Life-threatening Disease):**

- False negative (missing actual disease) is DEVASTATING
- Patient thinks they're healthy but isn't
- Could lead to death
- Solution: High recall (catch all potential cases)
- Trade-off: Some false alarms (further testing needed)

**Fraud Detection in Banking:**

- False negative (missing actual fraud) is VERY COSTLY
- Bank loses money
- Solution: High recall (flag all suspected fraud)
- Trade-off: Some false positives (verify transactions)

**Cancer Detection:**

- False negative (missing cancer) is CRITICAL
- Disease progresses undetected
- Solution: High recall (catch all possible cancers)
- Trade-off: Some false alarms (further investigation)

**When to Use:**

- ✓ Cost of false negative is high
- ✓ Must catch all positives
- ✓ Incomplete information acceptable
- ✗ When false positives are costly

### 4. Specificity (True Negative Rate)

**Definition:** Of the actual negative instances, how many did we correctly identify?

**Formula:**

```
Specificity = TN / (TN + FP)
```

**Interpretation:**

- Measures how well we identify negatives
- Inverse of false positive rate
- Higher specificity = fewer false alarms

**Relationship:**

```
Specificity = 1 - False Positive Rate
False Positive Rate = 1 - Specificity
```

### 5. F1 Score (Harmonic Mean)

**Problem with Precision and Recall:**

- High precision but low recall = missing positives
- High recall but low precision = too many false alarms
- Need a **balanced metric**

**Solution: F1 Score**

**Definition:** Harmonic mean of precision and recall

**Formula:**

```
Harmonic Mean = 2xy / (x + y)

F1 Score = 2 × (Precision × Recall) / (Precision + Recall)
```

**Why Harmonic Mean?**

- Emphasizes balance more than arithmetic mean
- Penalizes if either component is very low
- E.g., Precision=1, Recall=0 → F1=0, not 0.5

**Interpretation:**

- Range: 0 to 1
- 1.0 = Perfect (both precision and recall are 100%)
- 0.5 = Both components at reasonable levels
- Best when you need balance between precision and recall

**When to Use:**

- ✓ Imbalanced dataset
- ✓ Need balance between false positives and false negatives
- ✓ Want single metric for comparison
- ✗ When one metric is clearly more important

### Quick Reference: When to Use Which Metric

| Metric          | Best For                             |
| --------------- | ------------------------------------ |
| **Accuracy**    | Balanced data, all errors equal      |
| **Precision**   | Minimize false positives (high cost) |
| **Recall**      | Minimize false negatives (high cost) |
| **F1 Score**    | Imbalanced data, need balance        |
| **Specificity** | Emphasis on correct negatives        |

## 4. Multi-class Classification Metrics

### Extension to Multiple Classes

When there are **more than 2 classes**, confusion matrix expands.

### Example: Dog Breed Classifier

**Classes:** Husky (H), Labrador (L), Bulldog (B)

**Notation:** P(Actual, Predicted)

### Multi-class Confusion Matrix

```
             PREDICTED
           H    L    B
ACTUAL  H  P(H,H) P(H,L) P(H,B)
        L  P(L,H) P(L,L) P(L,B)
        B  P(B,H) P(B,L) P(B,B)
```

**Key Elements:**

- Diagonal: Correct predictions (True Positives for each class)
- Off-diagonal: Incorrect predictions
- **One-vs-All:** Calculate metrics for each class separately

### Calculating Metrics for Each Class

#### For Husky Class (treating Husky vs. not-Husky)

**True Positive (TP):** P(H,H)
**True Negative (TN):** P(L,L) + P(L,B) + P(B,L) + P(B,B) - P(H,L) - P(H,B)
**False Positive (FP):** P(L,H) + P(B,H)
**False Negative (FN):** P(H,L) + P(H,B)

#### For Labrador Class

**True Positive (TP):** P(L,L)
**True Negative (TN):** P(H,H) + P(H,B) + P(B,H) + P(B,B)
**False Positive (FP):** P(H,L) + P(B,L)
**False Negative (FN):** P(L,H) + P(L,B)

#### For Bulldog Class

**True Positive (TP):** P(B,B)
**True Negative (TN):** P(H,H) + P(H,L) + P(L,H) + P(L,L)
**False Positive (FP):** P(H,B) + P(L,B)
**False Negative (FN):** P(B,H) + P(B,L)

### Multi-class Accuracy

```
Accuracy = (P(H,H) + P(L,L) + P(B,B)) / Total Predictions
```

### Multi-class Precision

```
Precision(Husky) = P(H,H) / (P(H,H) + P(L,H) + P(B,H))
Precision(Labrador) = P(L,L) / (P(L,L) + P(H,L) + P(B,L))
Precision(Bulldog) = P(B,B) / (P(B,B) + P(H,B) + P(L,B))
```

### Multi-class Recall

```
Recall(Husky) = P(H,H) / (P(H,H) + P(H,L) + P(H,B))
Recall(Labrador) = P(L,L) / (P(L,L) + P(L,H) + P(L,B))
Recall(Bulldog) = P(B,B) / (P(B,B) + P(B,H) + P(B,L))
```

### Aggregation Methods

**Macro Average:**

- Calculate metric for each class separately
- Take simple average
- Example: Avg Precision = (Prec(H) + Prec(L) + Prec(B)) / 3
- All classes weighted equally

**Micro Average:**

- Calculate globally: Sum all TP / Sum all predictions
- Same as accuracy
- Weighted by support (class frequency)

## 5. ROC and AUC

### ROC Curve (Receiver Operating Characteristics)

**Purpose:** Evaluate classifier at all classification thresholds

**Axes:**

- X-axis: **False Positive Rate (FPR)** = FP / (FP + TN)
- Y-axis: **True Positive Rate (TPR)** = TP / (TP + FN)

**How It Works:**

- Vary threshold from 0 to 1
- For each threshold, calculate TPR and FPR
- Plot points on ROC curve
- Trace curve from (0,0) to (1,1)

### Important Points on ROC Space

**Point (0, 0):** Never predict positive

- No false positives, no true positives
- Conservative classifier
- Predict nothing → catch nothing

**Point (1, 1):** Always predict positive

- Catches everything but with many false alarms
- Liberal classifier
- Predict everything → catch everything

**Point (0, 1):** Perfect classification

- True positives = all
- False positives = none
- All predictions correct

**Diagonal Line (y = x):** Random guessing

- Performance equivalent to random chance
- No predictive power

### ROC Interpretation

**Better Classifier:**

- Curve closer to top-left (0, 1)
- Toward northwest
- Higher true positive rate for same false positive rate

**Classifier Classification:**

- **Conservative:** Lower-left region (few positives predicted)
- **Liberal:** Upper-right region (many positives predicted)
- **Random:** On diagonal line
- **Worse than random:** Below diagonal line

### Area Under Curve (AUC)

**Definition:** Area enclosed between ROC curve and x-axis

**Range:** 0 to 1

**Interpretation:**

| AUC         | Meaning                                 |
| ----------- | --------------------------------------- |
| **1.0**     | Perfect classifier (perfect separation) |
| **0.9-1.0** | Excellent discrimination                |
| **0.8-0.9** | Good discrimination                     |
| **0.7-0.8** | Fair discrimination                     |
| **0.6-0.7** | Poor discrimination                     |
| **0.5**     | Random chance (no skill)                |
| **< 0.5**   | Worse than random (systematic error)    |

**Use Cases:**

- ✓ Comparing classifiers (higher AUC = better)
- ✓ Imbalanced datasets
- ✓ Different threshold requirements
- ✓ Threshold-independent evaluation

**Advantage over Accuracy:**

- Works with imbalanced data
- Shows performance at all thresholds
- Single number for comparison

## 6. Worked Examples

### Example 1: Binary Classification Problem

**Given Confusion Matrix:**

```
              PREDICTED
           Positive  Negative
ACTUAL  +    100        5
        -     10       50
```

Total: n = 165

### Calculations

**Accuracy:**

```
Accuracy = (TP + TN) / Total
         = (100 + 50) / 165
         = 150 / 165
         = 0.909 = 90.9%
```

**Precision:**

```
Precision = TP / (TP + FP)
          = 100 / (100 + 10)
          = 100 / 110
          = 0.909 = 90.9%

When we predict positive, we're correct 90.9% of the time
```

**Recall (TPR):**

```
Recall = TP / (TP + FN)
       = 100 / (100 + 5)
       = 100 / 105
       = 0.952 = 95.2%

We catch 95.2% of actual positives
```

**Specificity (TNR):**

```
Specificity = TN / (TN + FP)
            = 50 / (50 + 10)
            = 50 / 60
            = 0.833 = 83.3%

We correctly identify 83.3% of actual negatives
```

**F1 Score:**

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
   = 2 × (0.909 × 0.952) / (0.909 + 0.952)
   = 2 × 0.865 / 1.861
   = 1.730 / 1.861
   = 0.930 = 93.0%

Good balance between precision and recall
```

### Example 2: Multi-class Classification

**Confusion Matrix:** Dog breed classification

```
         H    L    B
    H   100   80   10   (190 total)
    L    0    9    0    (9 total)
    B    0    1    8    (9 total)

    (100) (90) (18)
```

**Accuracy:**

```
Accuracy = (100 + 9 + 8) / 230
         = 117 / 230
         = 0.509 = 50.9%
```

**For Husky Class (TP=100):**

TP = 100 (H predicted as H)
FP = 80 + 1 = 81 (not-H predicted as H)
FN = 80 + 10 = 90 (H predicted as not-H)

```
Precision(H) = 100 / (100 + 81) = 100 / 181 = 0.552
Recall(H) = 100 / (100 + 90) = 100 / 190 = 0.526
```

**For Labrador Class (TP=9):**

TP = 9
FP = 80 + 1 = 81
FN = 0 + 0 = 0

```
Precision(L) = 9 / (9 + 81) = 9 / 90 = 0.100
Recall(L) = 9 / (9 + 0) = 9 / 9 = 1.0
```

**For Bulldog Class (TP=8):**

TP = 8
FP = 10 + 0 = 10
FN = 0 + 1 = 1

```
Precision(B) = 8 / (8 + 10) = 8 / 18 = 0.444
Recall(B) = 8 / (8 + 1) = 8 / 9 = 0.889
```

## 7. Class Skew and Imbalance

### Problem of Imbalanced Data

**Definition:** When classes are not equally represented in dataset

**Example:** Fraud detection

- Normal transactions: 99.9%
- Fraudulent: 0.1%

### Effect on Metrics

**Metrics Affected:**

- Accuracy (misleading with imbalance)
- Precision (biased toward majority class)
- F-Score (depends on class weights)

**Metrics Less Affected:**

- Recall (per-class basis)
- Precision (per-class basis)
- ROC/AUC (threshold-independent)

### Solutions for Imbalanced Data

1. **Resample:**
   - Oversample minority class
   - Undersample majority class
   - SMOTE (Synthetic Minority Oversampling)

2. **Use Different Metrics:**
   - Avoid accuracy
   - Use F1-score
   - Use ROC/AUC

3. **Adjust Class Weights:**
   - Give higher weight to minority class
   - Adjust model loss function

## Summary Tables

### All Metrics at a Glance

| Metric          | Formula               | Asks                     | Use When         |
| --------------- | --------------------- | ------------------------ | ---------------- |
| **Accuracy**    | (TP+TN)/(TP+TN+FP+FN) | Correct overall?         | Balanced classes |
| **Precision**   | TP/(TP+FP)            | When predict +, correct? | FP costly        |
| **Recall**      | TP/(TP+FN)            | Catch all positives?     | FN costly        |
| **Specificity** | TN/(TN+FP)            | Catch all negatives?     | TN important     |
| **F1**          | 2(P×R)/(P+R)          | Balance P and R?         | Imbalanced data  |

### Decision Matrix: Choose Your Metric

| Scenario               | Best Metric  | Reason                                       |
| ---------------------- | ------------ | -------------------------------------------- |
| Spam detection         | Precision    | False positives (real emails as spam) costly |
| Cancer diagnosis       | Recall       | False negatives (missing cancer) critical    |
| Credit approval        | Accuracy     | Balance matters equally                      |
| Imbalanced dataset     | F1 / ROC-AUC | Accuracy misleading                          |
| Fraud detection        | Recall/ROC   | Must catch fraud, accept false alarms        |
| Product recommendation | Precision    | False positive (bad recommendation) bad      |
