## 1. Eager vs Lazy Learning

### Two Fundamental Approaches to Learning

#### Eager Learning

**Approach:** Build model BEFORE seeing test queries

**Process:**
1. Receive training data
2. Create/train a global model using training data
3. Store the model (small memory requirement)
4. For test queries: use model to predict directly

**Training Phase:**
- Computationally intensive
- Happens once upfront

**Test/Prediction Phase:**
- Very fast
- Just apply stored model

**Examples:**
- Decision Trees
- Linear/Logistic Regression
- Neural Networks
- Naive Bayes

**Memory:** Low (just model parameters)

**Example Workflow:**
```
Training Data → Train Decision Tree → Store Tree
Query → Apply Tree → Prediction (Fast!)
```

#### Lazy Learning

**Approach:** Defer all computation UNTIL test query arrives

**Process:**
1. Receive training data
2. Store entire training dataset in memory (minimal processing)
3. When test query arrives: Process training data to find prediction

**Training Phase:**
- Minimal computation
- Just store data (happens immediately)

**Test/Prediction Phase:**
- Computationally intensive
- Must search/process training data for every query

**Examples:**
- K-Nearest Neighbors (KNN)
- Instance-based learning
- Memory-based learning
- Kernel machines
- RBF networks

**Memory:** High (entire dataset stored)

**Example Workflow:**
```
Training Data → Store in Memory (Done!)
Query → Search through all data → Find K neighbors → Predict (Slow!)
```

### Key Difference: When Computation Happens

| Aspect | Eager Learning | Lazy Learning |
|--------|----------------|---------------|
| **Training** | Heavy | Light |
| **Testing** | Light | Heavy |
| **Memory** | Low | High |
| **Model** | Generalized | Instance-specific |
| **Speed** | Fast predictions | Slow predictions |
| **Scalability** | Better for large data | Struggles with large data |

## 2. Instance-Based Learning

### Definition

**Instance-based learning** (memory-based learning) is a family of algorithms that:
- Compare new problem instances with instances seen in training
- Store training instances in memory
- Use stored instances to make predictions

### Characteristics

1. **No explicit model creation:**
   - Unlike decision trees or regression models
   - No "learned" parameters or rules

2. **Lazy computation:**
   - Computation postponed until test time
   - Sometimes called "lazy learning"

3. **Memory-based:**
   - All training data stored in accessible form
   - Can be large for big datasets

4. **Direct comparison:**
   - New instance compared directly with training instances
   - Similarity determines prediction

### Algorithm Examples

- **KNN** (K-Nearest Neighbors) - Our focus
- **Kernel machines** - Use kernel similarity
- **RBF networks** (Radial Basis Function)
- **Case-based reasoning**

### Core Assumption

**Instances similar in input space are similar in output space**

"Similar things tend to behave similarly"

## 3. KNN Overview

### What is KNN?

**K-Nearest Neighbors** is a lazy learning algorithm that:
- Classifies instances based on their neighbors
- Can be used for both classification and regression
- Works on idea that similar objects tend to stay together

### Algorithm Steps

1. **Given:** Query instance (xq) to classify
2. **Step 1:** Find K nearest neighbors in training data
   - Use distance measure to calculate distances
   - Sort distances
   - Select K closest instances

3. **Step 2:** Determine prediction based on neighbors
   - **Classification:** Use mode (most common class among K neighbors)
   - **Regression:** Use mean (average value of K neighbors)

### Key Parameters

- **K:** Number of neighbors to consider
- **Distance Measure:** How to calculate "closeness"
- **Feature Scaling:** How to normalize features

### Inductive Bias of KNN

**Inductive Bias:** Set of assumptions learner uses to predict outputs for unseen inputs

**KNN's Inductive Bias:**
> "The classification of instance x will be most similar to the classification of the K other instances that are nearby"

**Meaning:** Proximity implies similarity

## 4. Distance Measures

### Why Distance Matters

Distance measure determines what "nearby" means. Different measures can give different neighbors!

### Common Distance Measures

#### 1. Euclidean Distance

**Formula:**
```
d = √(Σ(xi - yi)²)
  = √((x₁-y₁)² + (x₂-y₂)² + ... + (xₙ-yₙ)²)
```

**Characteristics:**
- Most commonly used
- Straight-line distance
- Geometric/intuitive
- Works well for continuous features
- Sensitive to feature scaling

**Example (2D):**
```
Point A: (2, 3)
Point B: (5, 7)
d = √((5-2)² + (7-3)²) = √(9 + 16) = √25 = 5
```

#### 2. Manhattan Distance (City Block / L1)

**Formula:**
```
d = Σ|xi - yi|
  = |x₁-y₁| + |x₂-y₂| + ... + |xₙ-yₙ|
```

**Characteristics:**
- Distance like navigating city blocks
- Sum of absolute differences
- Computationally simpler
- Less sensitive to outliers than Euclidean

**Example (2D):**
```
Point A: (2, 3)
Point B: (5, 7)
d = |5-2| + |7-3| = 3 + 4 = 7
```

#### 3. Minkowski Distance (Generalized)

**Formula:**
```
d = (Σ|xi - yi|^q)^(1/q)
```

**Parameterized by q:**
- **q = 1:** Manhattan distance
- **q = 2:** Euclidean distance
- **q = ∞:** Chebyshev distance (max difference)

**Characteristics:**
- Flexible generalization
- Can tune q for problem
- Unifies multiple measures

### Choosing Distance Measure

| Measure | Best For | Issues |
|---------|----------|--------|
| **Euclidean** | Continuous features | Sensitive to scaling |
| **Manhattan** | Mixed features | Less intuitive |
| **Minkowski** | Flexible/tuning | Need to choose q |

## 5. KNN for Classification and Regression

### KNN for Classification

#### Setup

- **Target function:** Discrete-valued, multiclass
- **Domain:** d-dimensional space (Rd)
- **Classes:** Set V = {v₁, v₂, v₃, ..., vₘ} (m classes)
- **Target:** f : Rd → V

### Algorithm: KNN Classification

**Training Phase:**
- Store each training example <x, f(x)>
- No model building needed

**Classification Phase:**

Given xq to classify:
1. Find K nearest neighbors X₁...Xₖ of xq
2. For each class v in V, count how many neighbors have label v
3. Assign xq the class with the **most votes** (mode)

**Prediction Formula:**
```
f(xq) = arg max Σ δ(v, f(xi))
        v∈V   i=1 to K

where δ(a,b) = 1 if a=b, else 0
```

**In English:** Predict the class that appears most frequently among the K neighbors

### Example: Medical Risk Assessment

**Training Data:**
| B.P. | Sugar | Hemoglobin | WBC | Risk |
|------|-------|-----------|-----|------|
| 100 | 120 | 12 | 6 | No |
| 110 | 130 | 14 | 5 | Yes |
| 120 | 110 | 11 | 7 | Yes |
| 100 | 140 | 13 | 7 | No |
| 115 | 140 | 11 | 6 | Yes |

**Query:** BP=100, Sugar=135, Hemo=12, WBC=8, k=3

**Step 1: Calculate Distances**

Using Euclidean distance from query to each point:
- Distance to point 1: 15.13
- Distance to point 2: 11.74
- Distance to point 3: 32.04
- Distance to point 4: 5.19 ← Closest
- Distance to point 5: 15.96

**Step 2: Find K=3 Nearest Neighbors**

Sorted by distance:
1. Point 4: 5.19 (Risk = No)
2. Point 2: 11.74 (Risk = Yes)
3. Point 1: 15.13 (Risk = No)

**Step 3: Vote**
- No: 2 votes
- Yes: 1 vote

**Prediction:** Risk = **NO**

### KNN for Regression

#### Setup

- **Target function:** Real-valued, continuous
- **Domain:** d-dimensional space (Rd)
- **Target:** f : Rd → R

### Algorithm: KNN Regression

**Training Phase:**
- Store each training example <x, f(x)>

**Regression Phase:**

Given xq:
1. Find K nearest neighbors X₁...Xₖ
2. Average their values

**Prediction Formula:**
```
f(xq) = (1/K) × Σ f(xi)  [i=1 to K]
```

**In English:** Predict the **average value** of the K neighbors

### Example: Height Prediction

**Training Data:**
| Height | Age | Weight |
|--------|-----|--------|
| 5.0 | 45 | 77 |
| 5.11 | 26 | 47 |
| 5.6 | 30 | 55 |
| 5.9 | 34 | 59 |
| 4.8 | 40 | 72 |
| 5.8 | 36 | 60 |
| 5.3 | 19 | 40 |
| 5.8 | 28 | 60 |
| 5.5 | 23 | 45 |
| 5.6 | 32 | 58 |

**Query:** Height=5.5, Age=38, find Weight when k=3

**Step 1: Calculate Distances**

From query point (5.5, 38) to each:
- To row 6: 2.022 (Weight = 60)
- To row 5: 2.118 (Weight = 72)
- To row 4: 4.019 (Weight = 59)
- To row 10: 6.00 (Weight = 58)
- ... (others further)

**Step 2: Find K=3 Nearest**

1. Row 6: 2.022 → Weight 60
2. Row 5: 2.118 → Weight 72
3. Row 4: 4.019 → Weight 59

**Step 3: Average**
```
Predicted Weight = (60 + 72 + 59) / 3 = 191 / 3 = 63.67
```

## 6. Finding the Appropriate Value of K

### Impact of K Value

**K is critical:** Different values give different neighbors!

### Example: Choosing K

**Problem:** 4 data points, 2 classes

| Point | X | Y | Class |
|-------|---|---|-------|
| A | 2 | 8 | Triangle |
| B | 3 | 9 | Triangle |
| C | 5 | 11 | Circle |
| D | 6 | 13 | Circle |

**Query Point:** xq = (4, 10)

**Distances:**
- xq to A: 2.82 (Triangle)
- xq to B: 1.414 (Triangle)
- xq to C: 1.414 (Circle)
- xq to D: 3.6055 (Circle)

### K=1 Result

**Nearest neighbors:** B (1.414) and C (1.414) - **Tie!**

**Problem:** Can't decide between two equally close points

### K=2 Result

**Nearest 2:** B (1.414) and C (1.414)

**Vote:** Triangle = 1, Circle = 1 - **Still a Tie!**

**Problem:** Even split, can't decide

### K=3 Result

**Nearest 3:**
1. B: 1.414 (Triangle)
2. C: 1.414 (Circle)
3. A: 2.82 (Triangle)

**Vote:** Triangle = 2, Circle = 1

**Prediction:** **Triangle** ✓

**Resolved:** Clear winner!

### K=4 Result

**Nearest 4:** All points

**Vote:** Triangle = 2, Circle = 2

**Problem:** Tie again!

### Rule: Choosing K

**For 2 classes (binary):**
- K should be **ODD**
- Avoids ties
- Example: K = 1, 3, 5, 7, 9, ...

**For 3+ classes:**
- K should be **EVEN** if 2 classes, **ODD** if 3+ classes
- Or use weighted voting

**General Guidelines:**
- **K too small:** Noise affects prediction, high variance
- **K too large:** Loses locality, high bias
- **Typical:** K = √n or 3-5 for small datasets
- **Tune via cross-validation**

## 7. Choosing Relevant Features

### Problem: Feature Relevance

**Question:** Which features are actually important for prediction?

**Impact:** Irrelevant features add noise to distance calculation

### Solution: Feature Engineering

1. **Domain knowledge:** Which features make sense?
2. **Statistical analysis:** Correlation with target
3. **Information gain:** Contribution to classification
4. **Dimensionality reduction:** PCA, feature selection

### Considerations

- **Too many features:** Curse of dimensionality
- **Too few features:** Miss important information
- **Redundant features:** Waste computation
- **Irrelevant features:** Add noise

## 8. Feature Scaling and Normalization

### Problem: Unequal Feature Ranges

**Example:** Medical data

| ID | Age (years) | Income (₹) |
|----|-------------|-----------|
| 1 | 25 | 80,000 |
| 2 | 30 | 100,000 |

**Euclidean distance:** √((30-25)² + (100000-80000)²)
                      = √(25 + 400000000)
                      = √400000025
                      ≈ **20,000**

**Problem:** Income dominates distance because it has much larger magnitude!

Age difference (5) is completely overshadowed by income difference (20,000).

### Solution: Normalization (Standardization)

**Formula (Z-score normalization):**
```
X' = (X - μ) / σ

where:
μ = mean of feature
σ = standard deviation
```

**Result:** Features scaled to mean=0, std=1

### Example: Normalizing Medical Data

**Age statistics:** μ = 33, σ = 6

Age 25 normalized: (25 - 33) / 6 = -8/6 = -1.33

**Income statistics:** μ = 86,000, σ = 20,591.26

Income 80,000 normalized: (80,000 - 86,000) / 20,591.26 = -0.292

**New normalized distance:**
√((−1.33 − (−0.447))² + (−0.292 − 0.608)²)
= √((−0.883)² + (−0.900)²)
= √(0.779 + 0.810)
= √1.589
= **1.26**

**Much better!** Now age and income contribute equally.

### Other Normalization Methods

| Method | Formula | Range |
|--------|---------|-------|
| **Z-score** | (X - μ) / σ | -∞ to +∞ (≈-3 to +3) |
| **Min-Max** | (X - min) / (max - min) | 0 to 1 |
| **Unit Length** | X / \|\|X\|\| | 0 to 1 |

### When to Use Normalization

- ✓ Features have different units
- ✓ Features have different ranges
- ✓ Using distance-based algorithm (KNN, K-means)
- ✗ Features should be weighted differently
- ✗ Tree-based algorithms (don't need it)

## 9. Curse of Dimensionality

### Problem Definition

**In high-dimensional spaces, points that should be "close" are often not.**

### Why This Matters for KNN

KNN assumes: "Similar input → Similar output"

**In high dimensions:** Points are so spread out that "close" neighbors aren't actually close!

### Mathematical Insight

**Setup:** Unit cube [0,1]^d

**Problem:** Find K=10 nearest neighbors in this d-dimensional space

**Question:** What fraction of the cube do we need to search?

**Answer:** If we search volume V, containing K points:
```
V ≈ K / n

Edge length ℓ of smallest hypercube containing K neighbors:
ℓ^d ≈ K / n
ℓ ≈ (K/n)^(1/d)
```

### Example Calculations

**Given:** n = 1000 (data instances), K = 10 (neighbors), d = dimensions

| d | (K/n)^(1/d) = ℓ | Coverage |
|---|------------------|----------|
| 1 | (0.01)^1 = 0.01 | 1% of space |
| 2 | (0.01)^(1/2) = 0.10 | 10% of space |
| 3 | (0.01)^(1/3) = 0.21 | 21% of space |
| 5 | (0.01)^(1/5) = 0.40 | 40% of space |
| 10 | (0.01)^(1/10) = 0.63 | 63% of space |
| 20 | (0.01)^(1/20) = 0.79 | 79% of space |

**Critical Observation:**
- In 1D: Need only 1% of space
- In 20D: Need 79% of space to find same 10 neighbors!

### Problem Implications

**As dimensions increase:**
1. Must search larger fraction of input space
2. "Neighbors" become far away
3. KNN assumption breaks down
4. All distances become approximately equal
5. No meaningful local structure remains

**Result:** KNN becomes no better than random guessing in very high dimensions!

### Solutions to Curse

1. **Dimensionality Reduction:**
   - PCA (Principal Component Analysis)
   - Feature selection
   - Embedding methods

2. **Local Sensitivity Hashing:**
   - Approximate nearest neighbors
   - Hash-based methods

3. **Use Different Algorithm:**
   - Tree-based methods
   - Kernel methods
   - Neural networks

4. **Feature Engineering:**
   - Domain knowledge
   - Remove irrelevant features

## 10. Weighted KNN

### Problem with Vanilla KNN

**Scenario:** K = 3, distances are very different:

- Neighbor 1: Distance 0.1 (Very close!)
- Neighbor 2: Distance 5.0 (Far away)
- Neighbor 3: Distance 5.1 (Far away)

**Vanilla KNN:** All neighbors get equal vote (1/3 each)

**Problem:** Far neighbors have same influence as close neighbors!

**Intuition:** Close neighbors should matter more!

### Solution: Distance-Weighted KNN

**Idea:** Weight contribution by inverse distance

**Formula:**
```
Weight(xi) = 1 / distance(xq, xi)^m

where m = power (usually 1 or 2)

Prediction = Σ(weight(xi) × class(xi)) / Σ(weight(xi))
```

### Example: Classification with Weighted KNN

**Scenario:** Binary classification (Red/Blue), K=5

**Neighbors with distances:**
- A: Distance 2.1, Class = Red
- B: Distance 1.8, Class = Blue
- C: Distance 2.0, Class = Red
- D: Distance 1.1, Class = Blue
- E: Distance 0.7, Class = Blue

**Vanilla KNN (K=5):**
- Red votes: 2
- Blue votes: 3
- **Prediction: Blue** ✓

**Weighted KNN (m=1):**

Weights:
- A: 1/2.1 = 0.476
- B: 1/1.8 = 0.556
- C: 1/2.0 = 0.500
- D: 1/1.1 = 0.909
- E: 1/0.7 = 1.428

Support:
- Red support: 0.476 + 0.500 = 0.976
- Blue support: 0.556 + 0.909 + 1.428 = 2.893

**Prediction: Blue** (max: 2.893 > 0.976) ✓

**Difference:** More confident in Blue prediction

### Weighted KNN Regression

**Formula:**
```
f(xq) = Σ(weight(xi) × f(xi)) / Σ(weight(xi))
```

### Advantages of Weighting

- ✓ Closer neighbors have more influence
- ✓ More stable predictions
- ✓ Can reduce effect of outliers
- ✓ Often improves accuracy

## 11. Advantages and Challenges of KNN

### Advantages (Pros)

✅ **Simple and Intuitive:**
- Easy to understand
- No complex math
- Visualizable

✅ **No Training Phase:**
- Just store data
- Can add new instances immediately
- New data doesn't affect old predictions

✅ **Versatile:**
- Works for classification and regression
- Works for any number of classes
- No assumptions about data distribution

✅ **Local Adaptation:**
- Can adapt to local patterns
- Different regions can have different decisions

✅ **Non-parametric:**
- No underlying model to learn
- Data speaks for itself

### Challenges (Cons)

❌ **Computational Cost - Prediction:**
- Must compute distance to ALL training points
- Expensive for large datasets (thousands or millions)
- Every prediction requires O(n) operations

❌ **Memory Requirements:**
- Must store entire training set
- Large datasets = huge memory usage
- No compression or abstraction

❌ **Doesn't Scale Well:**
- Large datasets: Slow predictions
- Large dimensionality: Curse of dimensionality
- Impractical for real-time systems

❌ **Sensitivity to Feature Scaling:**
- Features with larger magnitude dominate
- Requires careful normalization
- Wrong scaling = wrong predictions

❌ **Curse of Dimensionality:**
- High dimensions break the algorithm
- "Close" neighbors aren't actually close
- Local structure disappears

❌ **Parameter Tuning:**
- Must choose K carefully
- Different K for different problems
- No automatic selection

❌ **Feature Relevance:**
- All features treated equally
- Irrelevant features add noise
- Need good feature selection

### When to Use KNN

**Good Choices:**
- ✓ Small to medium datasets
- ✓ Low dimensionality (< 20 features)
- ✓ Local patterns matter
- ✓ Need interpretability
- ✓ Quick prototyping

**Avoid:**
- ✗ Very large datasets
- ✗ High-dimensional data
- ✗ Need fast predictions
- ✗ Limited memory
- ✗ Real-time systems

## 12. Worked Examples and Practice Problems

### Practice Problem 1: Medical Risk Assessment

**Problem:**
Given the following medical dataset, use KNN (K=3) to determine risk for a patient with:
- BP: 100
- Sugar: 135
- Hemoglobin: 12
- WBC: 8 thousand

**Training Data:**
| ID | BP | Sugar | Hemo | WBC | Risk |
|----|-----|-------|------|-----|------|
| A | 100 | 120 | 12 | 6 | No |
| B | 110 | 130 | 14 | 5 | Yes |
| C | 120 | 110 | 11 | 7 | Yes |
| D | 100 | 140 | 13 | 7 | No |
| E | 115 | 140 | 11 | 6 | Yes |

### Solution:

**Query point:** xq = (100, 135, 12, 8)

**Step 1: Calculate Euclidean distances**

Distance to A: √((100-100)² + (135-120)² + (12-12)² + (8-6)²)
            = √(0 + 225 + 0 + 4) = √229 ≈ 15.13

Distance to B: √((100-110)² + (135-130)² + (12-14)² + (8-5)²)
            = √(100 + 25 + 4 + 9) = √138 ≈ 11.74

Distance to C: √((100-120)² + (135-110)² + (12-11)² + (8-7)²)
            = √(400 + 625 + 1 + 1) = √1027 ≈ 32.04

Distance to D: √((100-100)² + (135-140)² + (12-13)² + (8-7)²)
            = √(0 + 25 + 1 + 1) = √27 ≈ 5.19 ← Closest

Distance to E: √((100-115)² + (135-140)² + (12-11)² + (8-6)²)
            = √(225 + 25 + 1 + 4) = √255 ≈ 15.96

**Step 2: Sort and select K=3**

| Point | Distance | Risk |
|-------|----------|------|
| D | 5.19 | No |
| B | 11.74 | Yes |
| A | 15.13 | No |
| E | 15.96 | Yes |
| C | 32.04 | Yes |

**K=3 Nearest:** D, B, A

**Step 3: Vote**
- No: 2 votes (D, A)
- Yes: 1 vote (B)

**Prediction:** **Risk = NO**
