## 1. Introduction to Decision Trees

### What is a Decision Tree?

**Definition:** A decision tree is a flowchart-like diagram used to make decisions based on a series of conditions.

**Key Characteristics:**
- Represents learned function visually
- Can be converted to if-then rules for human readability
- Used for both classification and regression
- Hierarchical tree structure with branching

### How Decision Trees Work

Decision trees classify instances by sorting them down the tree from root to leaf node.

**Process:**
1. Start at root node (top)
2. Test attribute at each node
3. Follow branch based on attribute value
4. Continue until reaching leaf node
5. Leaf node provides classification

### Example: Loan Application Decision Tree

```
                    Income Range
                    /     |      \
                <30K    30-70K    >70K
               /         |          \
           Reject    Credit Card    Approve
                    Outstanding
                    /          \
                  High         Medium/Low
                  /              \
              Reject          Continue...
```

### Applications of Decision Trees

**Classification:**
- Credit approval (Approve/Reject)
- Medical diagnosis (Disease/Healthy)
- Email filtering (Spam/Not Spam)

**Regression:**
- Predicting continuous values
- House price estimation
- Temperature forecasting

## 2. Decision Tree Fundamentals

### Tree Structure Components

#### Root Node
- Topmost node where tree building starts
- Tests initial attribute
- All instances flow through root
- Most important decision point

#### Decision Nodes
- Internal nodes where branching occurs
- Test specific attribute
- Multiple decision nodes exist in tree
- Determine which branch to follow

#### Branches
- Correspond to possible values of attribute being tested
- Connect decision nodes
- One branch per attribute value
- Direct instances through tree

#### Leaf Nodes
- Terminal nodes with no children
- Contain classification decision
- End point of tree traversal
- Assign final classification label

### Example: Tennis Playing Decision Tree

```
                    Outlook
                  /    |    \
              Sunny  Overcast  Rainy
                |       |        |
            Humidity  Yes=Play  Wind
            /    \              /   \
          High  Normal        Weak  Strong
           No    Yes          Yes    No
```

**Classification Rules:**
- If Outlook=Sunny AND Humidity=Normal → Play=Yes
- If Outlook=Overcast → Play=Yes
- If Outlook=Rainy AND Wind=Weak → Play=Yes

### Key Properties

**Decision Tree Expressiveness:**
- More expressive than Find-S algorithm
- Represent disjunctions of conjunctions (OR of ANDs)
- Can learn complex relationships
- Handle both discrete and continuous attributes

**Example Expressiveness:**
```
Play = Yes IF:
  (Outlook=Sunny AND Humidity=Normal) OR
  (Outlook=Overcast) OR
  (Outlook=Rainy AND Wind=Weak)
```

## 3. Building Decision Trees: Step-by-Step Process

### Algorithm Overview

Decision tree construction follows systematic steps:

```
STEP 1: Select "best" decision attribute
          ↓
STEP 2: Assign attribute as node
          ↓
STEP 3: Create branch for each attribute value
          ↓
STEP 4: Sort training examples to new nodes
          ↓
STEP 5: Recursively repeat for each branch
          ↓
        Tree Complete
```

### Detailed Steps

**Step 1: Select Best Attribute**
- Calculate information gain for each attribute
- Choose attribute with highest information gain
- This is the "crux of the problem"
- Different algorithms use different criteria

**Step 2: Assign as Decision Node**
- Create node testing selected attribute
- Place at appropriate level in tree
- Connect to parent node

**Step 3: Create Branches**
- For each possible value of attribute
- Create descending branch
- Will depend on subset of instances

**Step 4: Sort Examples**
- Partition training data by attribute value
- Assign subsets to corresponding branches
- Each subset flows down one branch

**Step 5: Recursive Process**
- If training examples perfectly classified → STOP
- Otherwise, recursively apply steps 1-4
- Continue for each new leaf node
- Until all leaves are pure or stopping criteria met

### Multiple Decision Trees

**Important Insight:** Different trees can be built for same data!

```
Same Data Can Produce:

Option 1: Start with Performance
  Performance
    /        \
Above        Below
Average      Average
  |            |
Gender       Gender
/   \        /   \
...  ...    ...  ...

Option 2: Start with Gender
  Gender
   /    \
Girl     Boy
 |       |
Height  Performance
/  \    /      \
... ... ...    ...
```

**Question:** Which tree is better?

**Answer:** Depends on:
- Information gain of each attribute
- Tree size (simpler trees preferred)
- Algorithm being used (ID3, C4.5, CART)

## 4. Decision Tree Algorithms

### ID3 Algorithm (Iterative Dichotomiser 3)

**Developer:** Ross Quinlan (1986)

**Characteristics:**
- Creates multiway tree
- Uses greedy approach
- Finds categorical feature with largest information gain
- Places high-gain attributes near root
- Can be used for classification and regression

**Key Advantage:** Simple and intuitive

**Limitation:** Only handles discrete attributes

### C4.5 Algorithm

**Developer:** Ross Quinlan (extension of ID3)

**Improvements over ID3:**
- Handles continuous attributes
- Handles missing values
- Performs tree pruning
- Uses gain ratio instead of information gain
- More robust and practical

### CART Algorithm

**Developer:** Leo Breiman

**Full Name:** Classification and Regression Trees

**Characteristics:**
- Uses Gini Impurity (not entropy)
- Binary trees only (splits into 2 branches)
- For classification: uses Gini Index
- For regression: uses sum of least squares
- Includes automatic pruning
- More efficient than ID3/C4.5

### Comparison of Algorithms

| Aspect | ID3 | C4.5 | CART |
|--------|-----|------|------|
| **Split Criterion** | Information Gain | Gain Ratio | Gini Impurity |
| **Attribute Types** | Discrete only | Discrete/Continuous | Discrete/Continuous |
| **Tree Type** | Multiway | Multiway | Binary |
| **Missing Values** | No support | Handles | Handles |
| **Pruning** | No | Yes | Yes |
| **Speed** | Fast | Moderate | Fast |

## 5. ID3 Algorithm: Complete Foundation

### Information Gain Heuristic

ID3 uses **Information Gain** as the primary criterion for selecting best attribute.

**Goal:** Choose attribute that most reduces uncertainty/entropy

**Principle:** Select attribute that:
- Creates homogeneous subsets
- Reduces entropy most
- Brings us closest to classification

### Why ID3 Needs Information Gain

**Problem:** Many possible attributes to choose from

**Solution:** Use information gain to guide selection

**Benefit:** Greedy approach finds reasonably good tree quickly

### Algorithm Steps

```
ALGORITHM: ID3 (Iterative Dichotomiser 3)

INPUT: Training dataset S
       Set of attributes A

STEP 1: Calculate Entropy(S) for entire dataset
            ↓
STEP 2: For each attribute in A:
          - Calculate Entropy for each attribute value
          - Calculate average information entropy (weighted)
          - Calculate Information Gain
            ↓
STEP 3: Select attribute with HIGHEST Information Gain
        as decision node
            ↓
STEP 4: Create branches for each attribute value
            ↓
STEP 5: Recursively apply to each branch
        until all subsets are pure

OUTPUT: Decision tree
```

### Pseudocode

```
ID3(S, A):
  IF S is pure (all same class):
    RETURN Leaf(class)
  
  IF A is empty:
    RETURN Leaf(most common class in S)
  
  best_attribute ← attribute in A with highest gain
  
  FOR each value v of best_attribute:
    S_v ← {instances in S with best_attribute = v}
    child_tree ← ID3(S_v, A - {best_attribute})
    Add child_tree as branch for value v
  
  RETURN Tree with best_attribute at root
```

## 6. Information Gain Theory

### Definition

**Information Gain (I)** = Reduction in entropy when splitting dataset by an attribute

**Formula:**
```
Gain(S, A) = Entropy(S) - Entropy_after_split(S, A)
           = Entropy(S) - Σ(|S_v|/|S|) × Entropy(S_v)
```

Where:
- S = current dataset
- A = attribute being evaluated
- S_v = subset of S where attribute A has value v
- |S_v| = number of instances in subset
- |S| = total number of instances

### Understanding Information Gain

**What It Measures:**
- How much attribute reduces uncertainty
- Effectiveness of attribute for classification
- Degree of "purity" achieved by split

**Interpretation:**
- **High Gain:** Attribute creates very pure subsets
- **Low Gain:** Attribute doesn't help much
- **Zero Gain:** Attribute doesn't improve purity at all

**Greedy Strategy:**
- At each step, pick attribute with maximum gain
- Local optimization (not global)
- Good heuristic but no guarantee of optimal tree

### Calculation Process

**Step 1: Entropy Before Split**
- Calculate entropy of entire dataset S
- All instances mixed together

**Step 2: Entropy After Split**
- For each attribute value:
  - Create subset with that value
  - Calculate entropy of subset
- Calculate weighted average of all subsets

**Step 3: Compute Gain**
- Subtract entropy after from entropy before
- Result is information gain for this attribute

**Step 4: Compare Gains**
- Calculate gain for all attributes
- Select attribute with maximum gain

## 7. Entropy: Core Concept

### Definition

**Entropy** measures uncertainty or disorder in dataset.

**Meaning:** How "messy" or "impure" is the data?

**Formula:**
```
Entropy(S) = -Σ p(c_i) log₂ p(c_i)

Where:
  c_i = class i
  p(c_i) = proportion of instances with class c_i
  sum over all classes
```

### Understanding Entropy

**High Entropy:**
- Data is mixed (many classes)
- High uncertainty/disorder
- Need more information to classify
- Balanced class distribution

**Low Entropy:**
- Data is homogeneous (one class)
- Low uncertainty/order
- Easy to classify
- Imbalanced class distribution

**Zero Entropy:**
- Perfect purity (single class)
- No uncertainty
- Can classify with certainty
- All instances same class

**Maximum Entropy:**
- For binary classification: 1 bit
- For n-class: log₂(n)
- Equal proportion of all classes

### Entropy Visual Examples

**Bucket 1 (HIGH ENTROPY):**
- 50% Red, 25% Yellow, 25% Green
- Entropy ≈ 1.5 bits
- Highly uncertain which ball appears
- Random draws unpredictable

**Bucket 2 (MEDIUM ENTROPY):**
- 75% Red, 25% Green
- Entropy ≈ 0.81 bits
- Likely Red but some uncertainty
- Predictable most of time

**Bucket 3 (ZERO ENTROPY):**
- 100% Red
- Entropy = 0 bits
- Certain outcome
- Always Red

### Entropy Calculation Example

**Dataset: 14 instances**
- Class Yes: 9 instances (p=9/14=0.643)
- Class No: 5 instances (p=5/14=0.357)

**Entropy Calculation:**
```
E(S) = -[p(Yes)×log₂(p(Yes)) + p(No)×log₂(p(No))]
     = -[0.643×log₂(0.643) + 0.357×log₂(0.357)]
     = -[0.643×(-0.637) + 0.357×(-1.485)]
     = -[-0.410 - 0.530]
     = 0.94 bits
```

**Interpretation:** With 0.94 bits uncertainty, we need about 0.94 binary questions on average to classify instances.

### Entropy Reduction Through Splitting

**Original Dataset:** Entropy = 0.94

**After splitting by Outlook:**
- Sunny subset: Entropy = 0.971
- Overcast subset: Entropy = 0 (pure!)
- Rainy subset: Entropy = 0.971

**Weighted Average:**
```
I(Outlook) = (5/14)×0.971 + (4/14)×0 + (5/14)×0.971
           = 0.693
```

**Information Gain:**
```
Gain(S, Outlook) = 0.94 - 0.693 = 0.247
```

**Interpretation:** Outlook attribute reduces entropy by 0.247 bits.

## 8. Complete Worked Examples

### Example 1: Tennis Playing Dataset

**Dataset:**

| Outlook | Temperature | Humidity | Wind | Play Tennis |
|---------|------------|----------|------|------------|
| Sunny | High | High | Weak | No |
| Sunny | High | High | Strong | No |
| Overcast | High | High | Weak | Yes |
| Rainy | Medium | High | Weak | Yes |
| Rainy | Cool | Normal | Weak | Yes |
| Rainy | Cool | Normal | Strong | No |
| Overcast | Cool | Normal | Strong | Yes |
| Sunny | Medium | High | Weak | No |
| Sunny | Cool | Normal | Weak | Yes |
| Rainy | Medium | Normal | Weak | Yes |
| Sunny | Medium | Normal | Strong | Yes |
| Overcast | Medium | High | Strong | Yes |
| Overcast | High | Normal | Weak | Yes |
| Rainy | Medium | High | Strong | No |

**Task:** Build decision tree using ID3 algorithm

### Solution: Step-by-Step

**STEP 1: Calculate Initial Entropy**

```
Total instances: |S| = 14
Yes: 9 instances, No: 5 instances

p(Yes) = 9/14 = 0.643
p(No) = 5/14 = 0.357

Entropy(S) = -[0.643×log₂(0.643) + 0.357×log₂(0.357)]
           = -[-0.410 - 0.530]
           = 0.94 bits
```

**STEP 2: Calculate Entropy for Outlook Split**

**Sunny branch:** 5 instances (2 Yes, 3 No)
```
E(S_sunny) = -[2/5×log₂(2/5) + 3/5×log₂(3/5)]
           = -[(0.4×(-1.32)) + (0.6×(-0.737))]
           = 0.971 bits
```

**Overcast branch:** 4 instances (4 Yes, 0 No)
```
E(S_overcast) = -[4/4×log₂(4/4) + 0/4×log₂(0/4)]
               = 0 bits (pure!)
```

**Rainy branch:** 5 instances (3 Yes, 2 No)
```
E(S_rainy) = -[3/5×log₂(3/5) + 2/5×log₂(2/5)]
            = 0.971 bits
```

**Average Information:**
```
I(Outlook) = (5/14)×0.971 + (4/14)×0 + (5/14)×0.971
           = 0.347 + 0 + 0.347
           = 0.693 bits
```

**Information Gain:**
```
Gain(S, Outlook) = 0.94 - 0.693 = 0.247
```

**STEP 3: Calculate Entropy for Temperature Split**

**High branch:** 4 instances (2 Yes, 2 No)
```
E(S_high) = -[2/4×log₂(2/4) + 2/4×log₂(2/4)]
           = 1 bit
```

**Medium branch:** 6 instances (4 Yes, 2 No)
```
E(S_medium) = -[4/6×log₂(4/6) + 2/6×log₂(2/6)]
             = 0.918 bits
```

**Cool branch:** 4 instances (3 Yes, 1 No)
```
E(S_cool) = -[3/4×log₂(3/4) + 1/4×log₂(1/4)]
           = 0.811 bits
```

**Average Information:**
```
I(Temperature) = (4/14)×1 + (6/14)×0.918 + (4/14)×0.811
                = 0.286 + 0.394 + 0.232
                = 0.911 bits
```

**Information Gain:**
```
Gain(S, Temperature) = 0.94 - 0.911 = 0.029
```

**STEP 4: Calculate Entropy for Humidity Split**

**High branch:** 7 instances (3 Yes, 4 No)
```
E(S_high) = -[3/7×log₂(3/7) + 4/7×log₂(4/7)]
           = 0.985 bits
```

**Normal branch:** 7 instances (6 Yes, 1 No)
```
E(S_normal) = -[6/7×log₂(6/7) + 1/7×log₂(1/7)]
             = 0.592 bits
```

**Average Information:**
```
I(Humidity) = (7/14)×0.985 + (7/14)×0.592
             = 0.493 + 0.296
             = 0.789 bits
```

**Information Gain:**
```
Gain(S, Humidity) = 0.94 - 0.789 = 0.151
```

**STEP 5: Calculate Entropy for Wind Split**

**Weak branch:** 8 instances (6 Yes, 2 No)
```
E(S_weak) = -[6/8×log₂(6/8) + 2/8×log₂(2/8)]
           = 0.811 bits
```

**Strong branch:** 6 instances (3 Yes, 3 No)
```
E(S_strong) = -[3/6×log₂(3/6) + 3/6×log₂(3/6)]
             = 1 bit
```

**Average Information:**
```
I(Wind) = (8/14)×0.811 + (6/14)×1
        = 0.463 + 0.429
        = 0.892 bits
```

**Information Gain:**
```
Gain(S, Wind) = 0.94 - 0.892 = 0.048
```

**STEP 6: Compare All Information Gains**

| Attribute | Information Gain |
|-----------|-----------------|
| **Outlook** | **0.247** ← Maximum |
| Temperature | 0.029 |
| Humidity | 0.151 |
| Wind | 0.048 |

**Decision:** Choose **Outlook** as root node!

**STEP 7: Build Root Node**

```
                    Outlook
                  /    |    \
              Sunny  Overcast Rainy
                |       |       |
              (5)      (4)     (5)
```

**Note:** Overcast branch is pure (all 4 are Yes), so it becomes leaf.

**STEP 8: Recursively Process Sunny Branch**

**Data for Sunny branch:** 5 instances (2 Yes, 3 No)

Calculate entropy: E(S_sunny) = 0.971

Calculate gains for remaining attributes:
- Gain(S_sunny, Temperature) = 0.571
- Gain(S_sunny, Humidity) = 0.971 ← Maximum
- Gain(S_sunny, Wind) = 0.02

Choose Humidity for Sunny node!

```
Humidity split:
- High: 2 instances (0 Yes, 2 No) → Entropy = 0 → Leaf "No"
- Normal: 3 instances (2 Yes, 1 No) → Entropy > 0 → Continue
```

**STEP 9: Recursively Process Rainy Branch**

Similar process produces:

```
Wind split:
- Weak: 3 instances (3 Yes, 0 No) → Entropy = 0 → Leaf "Yes"
- Strong: 2 instances (0 Yes, 2 No) → Entropy = 0 → Leaf "No"
```

**STEP 10: Final Decision Tree**

```
                        Outlook
                     /    |    \
                 Sunny  Overcast Rainy
                  |       |       |
               Humidity  Yes     Wind
               /    \            /   \
             High  Normal      Weak  Strong
              |      |          |      |
             No    Continue    Yes    No
```

### Example 2: Job Acceptance Dataset

**Dataset:**

| Salary | Location | Job Acceptance |
|--------|----------|----------------|
| Tier1 | MUM | Yes |
| Tier1 | BLR | Yes |
| Tier2 | BLR | No |
| Tier1 | HYD | No |
| Tier2 | MUM | Yes |
| Tier1 | HYD | No |

**Task:** Build decision tree to predict job acceptance

### Solution: Step-by-Step

**STEP 1: Initial Entropy**

```
Total: 6 instances
Yes: 3 instances (p=0.5)
No: 3 instances (p=0.5)

E(S) = -[0.5×log₂(0.5) + 0.5×log₂(0.5)]
     = 1 bit (maximum uncertainty)
```

**STEP 2: Split by Salary**

**Tier1 branch:** 3 instances (2 Yes, 1 No)
```
E(S_Tier1) = -[2/3×log₂(2/3) + 1/3×log₂(1/3)]
            = 0.918 bits
```

**Tier2 branch:** 3 instances (1 Yes, 2 No)
```
E(S_Tier2) = -[1/3×log₂(1/3) + 2/3×log₂(2/3)]
            = 0.918 bits
```

**Average Information:**
```
I(Salary) = (3/6)×0.918 + (3/6)×0.918 = 0.918
```

**Gain(S, Salary) = 1 - 0.918 = 0.082**

**STEP 3: Split by Location**

**MUM branch:** 2 instances (2 Yes, 0 No)
```
E(S_MUM) = 0 bits (pure!)
```

**BLR branch:** 2 instances (1 Yes, 1 No)
```
E(S_BLR) = 1 bit
```

**HYD branch:** 2 instances (0 Yes, 2 No)
```
E(S_HYD) = 0 bits (pure!)
```

**Average Information:**
```
I(Location) = (2/6)×0 + (2/6)×1 + (2/6)×0 = 0.333
```

**Gain(S, Location) = 1 - 0.333 = 0.667**

**STEP 4: Compare Gains**

| Attribute | Gain |
|-----------|------|
| Salary | 0.082 |
| **Location** | **0.667** ← Choose |

**STEP 5: Final Tree**

```
                    Location
                   /   |    \
                MUM   BLR   HYD
                 |     |     |
                Yes   Need  No
                      More Split
```

Since BLR is mixed, split recursively by Salary:
```
                    Location
                   /   |    \
                MUM   BLR   HYD
                 |     |     |
                Yes   Salary No
                     /   \
                  Tier1  Tier2
                    |      |
                   Yes    No
```
