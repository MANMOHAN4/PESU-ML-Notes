## Positioning Reinforcement Learning

### Interdisciplinary Nature

**RL combines concepts from multiple disciplines:**

- **Computer Science** → Algorithms, computation, data structures
- **Engineering** → Control systems and robotics
- **Neuroscience** → How the brain learns through reward and punishment
- **Mathematics & Operations Research** → Optimization, Markov processes, probability
- **Economics** → Decision-making, optimal strategies, reward maximization
- **Psychology** → Learning from trial and error, behavior conditioning

### Key Integration

**Reinforcement Learning** enables agents to learn autonomously through experience and reward signals, combining insights from all these fields.

## What Characterizes RL

### Key Differences from Other ML Tasks

**1. No Supervisor:**
- System doesn't get labeled data
- Only receives reward signals based on actions
- Must learn from consequences, not explicit examples

**2. Delayed Feedback:**
- Reward may come after several actions
- Not immediately after each action
- Makes learning more challenging (credit assignment problem)

**3. Time Matters:**
- Learning happens over sequences of states and actions
- Temporal process (not one-shot)
- History and causality important

**4. Action Affects Data:**
- Agent's actions change future inputs
- Environment becomes non-stationary
- Creates feedback loops between learning and exploration

## What is Reinforcement Learning

### Core Definition

**Reinforcement Learning (RL)** is a type of Machine Learning where:
- Agent learns by **interacting with an environment**
- Receives **rewards** (positive or negative feedback) based on actions
- **Objective:** Learn a strategy (policy) that maximizes cumulative reward over time
- **Learning method:** Trial and error (not labeled data)

### Key Contrast with Supervised Learning

| Aspect | Supervised Learning | RL |
|--------|-------------------|-----|
| **Training data** | Labeled examples | Unlabeled, only rewards |
| **Feedback** | Immediate and complete | Delayed and partial |
| **Environment** | Static | Dynamic/non-stationary |
| **Agent role** | Passive observer | Active participant |

## RL Cycle

### Two Core Entities

**1. Agent:** The learner or decision-maker

**2. Environment:** The system the agent interacts with

### Cycle of Interaction

```
Agent observes state St
  ↓
Agent takes action At
  ↓
Environment processes action
  ↓
Environment returns reward Rt+1 and new state St+1
  ↓
(Loop continues)
```

### Information Flow

**Agent at each step t:**
- Takes action At
- Observes observation Ot
- Receives reward Rt

**Environment at each step t:**
- Receives action At
- Returns new observation Ot+1
- Returns reward Rt+1

**Result:** Continuous feedback loop where agent learns from consequences

### Example: Super Mario

```
State (St): Mario's position, enemies visible
  ↓
Action (At): Move right, jump, or stay
  ↓
Reward (Rt+1): +1 for collecting coins, -1 for losing life
  ↓
New State (St+1): Updated Mario position and world state
  ↓
(Process repeats)
```

## History and State

### History Definition

**History (Ht)** = Sequence of observations, actions, and rewards up to time t

```
Ht = (O1, A1, R1, O2, A2, R2, ..., Ot, At, Rt)
```

**Represents:** All sensorimotor stream of robot/embodied agent

### What Happens Next Depends On

**Determining next action:**
- Agent uses history to decide next move
- Current state should contain sufficient information

**Determining environment response:**
- Environment uses history to generate next reward/observation
- Typically only depends on current state (Markov property)

### State Definition

**State (St)** = Information used to determine what happens next

**Key Property:** State is a compressed representation of history that's sufficient for decision-making

**Mathematical Form:**
```
St = f(History_t)
```

**Principle:** State contains only the relevant information from history, discarding irrelevant details

## Environment State vs Agent State

### Environment State

**Definition:** Private representation of environment at time t

**What it represents:**
- Information the environment uses to generate next reward/observation
- Not usually visible to the agent (unobservable environment)

**Important:** Even if visible, might contain irrelevant information

**Examples:**
- Robot can't "see" the full map, only what sensors show
- Self-driving car doesn't know other drivers' intentions (hidden state)
- Video game has hidden internal state not shown on screen

### Agent State

**Definition:** Internal representation owned by agent

**What it represents:**
- Information agent uses to select next action
- Agent's internal understanding of the world
- Function of history: St^a = σ(Wh × St-1^a + Wo × Ot)

**Key Insight:** Agent doesn't know everything - must build mental model from experience

### Gap Between States

**Challenge:**
- Environment state (St^e) often differs from agent state (St^a)
- Agent must infer hidden states from observations
- In POMDPs, this becomes significant challenge

**Solution:**
- Use recurrent networks (RNNs/LSTMs) for memory
- Maintain beliefs about hidden state
- Learn state representation from data

## Elements of RL

### Fundamental Components

**1. States (S):**
- Representation of current world or environment
- Describes situation agent finds itself in
- Example: Chess board position, game score

**2. Actions (A):**
- Something RL agent can do to change states
- Agent's control interface on environment
- Example: Move piece, press button, turn wheel

**3. Reward Function (R):**
- Maps each state (or state-action pair) to real number
- R: S → ℝ or R: S × A → ℝ
- Defines utility the agent receives
- Example: +1 for win, -1 for loss, 0 for nothing

**4. Rewards:**
- The utility agent receives for performing "right" actions
- Actual values sampled from reward function
- Provides feedback on action quality

**5. Policy (π):**
- Map from state space to action space
- π: S → A (deterministic) or π: S × A → [0,1] (stochastic)
- Agent's behavior/decision-making strategy
- Can be stochastic (probability distribution over actions)

**6. Value Function (V):**
- Total expected reward starting from state s
- V(s) = E[Gt | St = s]
- Evaluates long-term goodness of states
- Helps guide decision-making

## Markov Decision Process

### Building Towards MDP

**Markov Process (MP) / Markov Chain:**
- All possible states form "State Space"
- States directly observable
- Future depends only on current state (Markov Property)
- Notation: State transition table

**Markov Rewards Process (MRP):**
- All properties of MP
- Plus notion of rewards included
- Two tables: state transition table + rewards table

**Markov Decision Process (MDP):**
- All properties of MRP
- Plus "actions" added
- State transition indexed by action: (i, j, a)
- Gives agent control over transitions

### The Markov Property

**Mathematical Statement:**
```
P(St+1 | S1, ..., St) = P(St+1 | St)
```

**Meaning:** Future state depends only on present, not on past

**Why Important:**
- Simplifies learning (only need current state)
- Makes problems tractable
- Example: To predict next chess move, need current board position, not game history

**Intuition:**
- If you know current position and speed, you can predict next position
- Don't need your entire travel history
- Current state "contains" all relevant information

---

## MDP Mathematical Definition

### Complete Specification

**MDP is defined by tuple: (S, A, R, P, γ)**

| Symbol | Meaning |
|--------|---------|
| **S** | Set of all possible states |
| **A** | Set of possible actions |
| **R** | Reward function: R(s, a) = expected immediate reward for action a in state s |
| **P** | Transition probability: P(s' \| s, a) = probability of transitioning to state s' after taking action a in state s |
| **γ** | Discount factor: controls importance of future rewards (0 ≤ γ ≤ 1) |

### Interpretation

**States (S):**
- Discrete: Chess positions, grid cells
- Continuous: Robot position, temperature

**Actions (A):**
- Discrete: Move up/down/left/right
- Continuous: Steering angle, throttle

**Rewards (R):**
- Function of state and/or action
- Scalar feedback signal
- Can be positive, negative, or zero

**Transitions (P):**
- Often stochastic (probabilistic)
- Must be well-defined for all valid (s, a) pairs
- Sum to 1: Σs' P(s' | s, a) = 1

**Discount Factor (γ):**
- Controls tradeoff between immediate and future rewards
- Mathematical convenience (avoid infinite returns)
- Human-like behavior modeling

---

## Discount Factor

### Purpose

**Mathematical Convenient:**
- Avoids infinite returns and values
- Ensures convergence in infinite-horizon problems

**Behavioral Modeling:**
- Humans often act as if there's discount factor < 1
- Reflects preference for immediate rewards

### Effect of Different Values

**γ = 0:**
- Agent only cares about immediate reward
- Myopic (short-sighted) behavior
- No long-term planning

**0 < γ < 1:**
- Balances immediate and future rewards
- Typical case in practice
- Exponential decay of future importance

**γ = 1:**
- Future reward as beneficial as immediate reward
- Can use if episode lengths always finite
- Treats all time equally

### Typical Values

- **0.9:** Short-term focus (useful when future uncertain)
- **0.99:** Longer-term planning (standard in many algorithms)
- **0.999:** Very long-term planning (for complex tasks)

### Mathematical Implication

**Undiscounted return:**
```
G = R0 + R1 + R2 + ...
(Can be infinite)
```

**Discounted return:**
```
G = R0 + γR1 + γ²R2 + ...
(Converges if |γ| < 1)
```

## Reward in MDP

### Reward Distribution

**General form:**
```
Rt ~ R(· | St, At)
```

**Simplified assumption:**
```
Rt = r(St, At)
```

**Meaning:**
- Reward may depend on current state
- Reward may depend on action taken
- Example: Reward for going right from position (x, y)

### Return Definition

**Return (Gt)** = Total cumulative future reward

**Undiscounted:**
```
G = R0 + R1 + R2 + ...
```

**Discounted:**
```
G = R0 + γR1 + γ²R2 + ...
```

### RL Objective

**Goal:** Maximize expected return
```
Maximize E[G]
```

**Policy determines:**
- Which actions taken in each state
- Distribution over returns
- Expected cumulative reward

### Discount Factor Effect

**Large γ (close to 1):**
- Future rewards matter significantly
- Encourages long-term planning
- More stable but slower learning

**Small γ (close to 0):**
- Only immediate rewards matter
- Encourages short-term behavior
- Faster learning but myopic policies

## Policy

### Definition

**Policy (π)** = Agent's behavior strategy

**Mathematical form:**
- Maps states to actions
- Can be deterministic or stochastic

### Types of Policies

**1. Deterministic Policy:**
```
a = π(s)

Meaning: Given state s, always take action a
Example: In chess, "always move the rook forward"
```

**2. Stochastic Policy:**
```
π(a | s) = P(At = a | St = s)

Meaning: Probability distribution over actions given state
Example: 60% move rook, 40% move knight
```

### Policy Evaluation

**Question:** How good is policy π?

**Answer:** Value function tells us
```
V^π(s) = expected cumulative reward following π from state s
Q^π(s,a) = expected cumulative reward after taking a, then following π
```

### Policy Improvement

**Process:**
1. Evaluate current policy π
2. Update actions to improve expected rewards
3. Repeat until convergence

**Result:** Optimal policy π*

## Observability in Environments

### Fully Observable Environment

**Definition:** Agent directly observes full environment state

```
Observation = Environment State = Agent State
Ot = St^e = St^a
```

**Advantage:**
- Problem is simpler
- Modeled as Markov Decision Process (MDP)

**Example:**
- Simple grid world
- Agent knows exact position
- No uncertainty

### Partially Observable Environment

**Definition:** Agent can't see everything

```
Observation ≠ Environment State
Ot ≠ St^e
```

**Challenge:**
- Agent must infer full state from limited observations
- Makes learning harder (credit assignment unclear)

**Formal Model:** Partially Observable Markov Decision Process (POMDP)

### Handling Partial Observability

**Solution 1: Build Internal State Model**
```
St^a = σ(Ws × St-1^a + Wo × Ot)
```

**Solution 2: Use History as Pseudo-State**
```
St^a = St-n, St-n+1, ..., St (sliding window)
```

**Solution 3: Recurrent Networks**
- LSTMs or GRUs maintain memory
- Learn what to remember
- Infer hidden state automatically

### Examples

**Partially Observable:**
- Robot with camera only (doesn't know full map)
- Trading agent only sees current prices (not market internals)
- Game where opponent's hidden units unknown
- Poker (don't know opponent's cards)

## Maze Example - Complete Walkthrough

### Problem Setup

```
Grid environment:
┌─┬─┬─┬─┐
│S│ │ │ │
├─┼─┼─┼─┤
│ │█│ │ │  S = Start
├─┼─┼─┼─┤  █ = Wall
│ │ │ │ │  G = Goal
├─┼─┼─┼─┤
│ │█│ │G│
└─┴─┴─┴─┘
```

**Specifications:**
- States: Agent location (grid cells)
- Actions: N, E, W, S (up, right, left, down)
- Rewards: -1 per time step (encourages speed)
- Goal: Reach marked cell in minimum steps

### Policy Representation

**Optimal policy shown with arrows:**
```
┌─┬─┬─┬─┐
│→│→│→│↓│
├─┼─┼─┼─┤
│↑│█│↓│↓│
├─┼─┼─┼─┤
│↑│→│→│↓│
├─┼─┼─┼─┤
│←│█│←│G│
└─┴─┴─┴─┘
```

**Interpretation:**
- Each arrow shows optimal action from that state
- Policy guides agent from start to goal
- π(s) = recommended action for state s

### Value Function Representation

**Value function shown as numbers:**
```
┌────┬────┬────┬────┐
│ -3 │ -2 │ -1 │  0 │
├────┼────┼────┼────┤
│ -4 │ █  │ -1 │ -1 │
├────┼────┼────┼────┤
│ -5 │ -4 │ -3 │ -2 │
├────┼────┼────┼────┤
│ -6 │ █  │ -2 │ -1 │
└────┴────┴────┴────┘
```

**Interpretation:**
- V(s) = expected total reward starting from state s
- Closer to 0 = closer to goal
- More negative = farther away
- Formula: V^π(s) = E[Rt+1 + γRt+2 + ... | St = s]

### Model Representation

**Transition probabilities:**
```
P(s' | s, a): How taking action a in state s leads to state s'
```

**Rewards:**
```
R(s, a): Immediate reward for action a in state s
All transitions: R = -1
Goal state: R = 0
```

## Atari Example

### Reinforcement Learning Approach

**Setup:**
- Agent plays game without knowing rules
- Only sees pixel inputs (screen images)
- Only receives scores (rewards)
- Learns by trial and error

**Steps:**
1. **Observation (Ot):** See game screen (pixel data)
2. **Action (At):** Choose joystick move
3. **Reward (Rt):** Receive updated score
4. **Repeat:** Learn best policy through experience

### Planning Approach

**Different setup:**
- Rules of game are known
- Agent contains game emulator (model)
- Can simulate future moves mentally

**Capabilities:**
- If I take action a from state s:
  - What would next state be?
  - What would score be?
- Plan ahead using tree search
- Similar to chess engines

### Model-Based vs Model-Free

| Aspect | Model-Free (RL) | Model-Based (Planning) |
|--------|-----------------|----------------------|
| **Knowledge** | Game rules unknown | Game rules known |
| **Learning** | Trial and error | Simulation |
| **Time** | Must play many games | Can plan offline |
| **Real-world** | More applicable | Harder to get model |

## Value Functions

### Two Main Types

**1. State Value Function (V):**
```
V^π(s) = E_π[Gt | St = s]

Meaning: Expected total reward starting from state s, following policy π
Answer: "How good is this state?"
```

**2. Action Value Function (Q):**
```
Q^π(s, a) = E_π[Gt | St = s, At = a]

Meaning: Expected total reward after taking action a in state s, then following π
Answer: "How good is this state-action pair?"
```

### Relationship

```
V^π(s) = Σ_a π(a|s) Q^π(s, a)

Meaning: State value is weighted average of action values
```

### Why Both?

**V-function useful for:**
- Evaluating states
- Planning trajectory
- State comparison

**Q-function useful for:**
- Direct action selection
- Temporal difference learning
- Doesn't require model of environment

### Optimal Value Functions

**Optimal state value:**
```
V*(s) = max_π V^π(s)

Best possible reward from state s
```

**Optimal action value:**
```
Q*(s, a) = max_π Q^π(s, a)

Best possible reward after taking action a from state s
```

## Deep Q-Learning

### Problem with Tabular Q-Learning

**Limitation:**
- Works only when states are discrete and limited
- Example: 4×4 grid = 16 states (manageable)
- But Atari: 210×160×3 pixels = 256^100,800 states (impossible!)

**Solution:** Use neural network to approximate Q-function

### Deep Q-Learning Approach

**Core Idea:**
```
Replace Q-table with deep neural network
Q(s, a; θ) ≈ Q*(s, a)

Where:
- Input: state s and action a
- Output: estimated Q-value
- θ: neural network weights (parameters)
```

### Architecture

**Input:** State (or encoded state)
**Hidden Layers:** Fully connected layers (learn representations)
**Output:** Q-values for each action

```
[State Input]
     ↓
[Dense Layer 1] (128 neurons, ReLU)
     ↓
[Dense Layer 2] (128 neurons, ReLU)
     ↓
[Output Layer] (one neuron per action)
     ↓
[Q-values for all actions]
```

### Advantages

✅ **Scalability:** Handles high-dimensional states (images)
✅ **Generalization:** Network learns shared features
✅ **Stability:** Network smooths out Q-value estimates
✅ **Expressiveness:** Can learn complex value functions

### Training Process

1. Collect experience (state, action, reward, next state)
2. Compute target Q-value
3. Update network weights to minimize loss
4. Repeat

## Exploration vs Exploitation

### The Fundamental Tradeoff

**Exploration:**
- Try new actions to gather information
- Discover previously unknown good rewards
- Risky (might find worse rewards)
- Necessary for learning

**Exploitation:**
- Use best-known actions to maximize immediate reward
- Safe (stick with what you know works)
- Suboptimal if better options exist
- Prevents discovery

### Effective RL Requires Balance

**Too much exploration:**
- Learn a lot but accumulate little reward
- Inefficient (wasted episodes)

**Too much exploitation:**
- Accumulate reward quickly but miss better strategies
- Local optima (stuck in suboptimal policy)

### Examples

**Restaurant Selection:**
- **Exploitation:** Go to favorite restaurant every time
- **Exploration:** Try new restaurants regularly
- **Balance:** Go to favorite 80% of time, try new 20%

**Game Playing:**
- **Exploitation:** Play best-known move
- **Exploration:** Play experimental move
- **Balance:** 90% best move, 10% random move

**Autonomous Driving:**
- **Exploitation:** Follow learned safe driving pattern
- **Exploration:** Try alternative routes (carefully)
- **Balance:** Mostly known safe routes, sometimes try new paths

### Epsilon-Greedy Strategy

**Simple approach:**
- With probability ε: Take random action (explore)
- With probability 1-ε: Take best action (exploit)

**Example:** ε = 0.1
- 10% random actions (explore)
- 90% best actions (exploit)

**Adjustment:**
- Start with high ε (more exploration)
- Decrease ε over time (more exploitation)
